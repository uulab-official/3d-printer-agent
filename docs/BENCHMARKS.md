# 3D Printer Agent 벤치마크 계획

기준일: 2026-11-12. 작업명 `3d-printer-agent`; 제품명 미정.

**아래 30개 사례와 수치 목표는 평가 설계 제안이며 현재 성능·통과율이 아니다.** 기대 판정과 실제 결과를 분리한다. 성공·실패·미실행 결과는 주 실행 담당자가 같은 코드 버전의 검증 기록으로 별도 보고한다. 이 문서에 테스트 이름이 있거나 코드 경로가 존재하는 것만으로 통과했다고 간주하지 않는다.

## 1. 평가 범위와 증거 등급

| 구분 | 수행 환경 | 입증할 수 있는 것 | 입증할 수 없는 것 |
|---|---|---|---|
| O: 오프라인 | 고정 입력·가짜 실행 파일·보존한 응답 fixture | 파서, 계산, 판정, 파일 처리, 실패 처리의 재현성 | 실제 Bambu 동작, 외부 모델 품질, 현재 가격·서비스 조건 |
| N: 실제 네이티브 | 사용자의 PC와 실제 Bambu Studio | 해당 OS·앱 버전의 설치 탐지·설정 반영·슬라이싱 | 실물 출력 성공·기계적 강도 |
| L: 실제 연결 | 명시한 LLM·모델·자료 공급자·조회 시각 | 그 연결과 데이터 회수의 관측 결과 | 다른 공급자·버전·미래 시각에서의 동작 |
| H: 실물 | 기록한 프린터·재료·노즐·플레이트·조건 | 그 조건의 출력·치수·외관·조립 관측 | 모든 장비·재료의 성공률 |

O에서 실패 처리를 검증했다고 N/L/H를 통과로 표시하지 않는다. 현재 구현 상태는 [PRODUCT_ROADMAP.md](PRODUCT_ROADMAP.md)를 참조한다. 아래 “현재 코드 대상”은 실행할 경로가 있다는 뜻이며 성공 판정이 아니다. “확장 필요”는 평가 전에 해당 기능·fixture·접근을 마련해야 한다는 뜻이다.

## 2. 공통 실행 기록

각 실행에는 case ID, 시각, 코드 버전·변경 상태, 입력 원문·해시, OS·앱·모델 버전, 관측 장비 조건, 예상 결과, 실제 응답, 산출물·로그, 실행자가 확인한 범위를 남긴다. 외부 자료는 발행처·URL·회수 시각·내용 해시를 추가한다. 사용자 보고와 자동 검사와 실측은 구분한다.

결과 상태는 `pass / fail / not_run / not_applicable`로 기록한다. 도구가 없어 실행하지 못했으면 `not_run`이지 pass가 아니다. 미실행 항목을 통과율의 분자·분모에서 조용히 제외하지 말고 별도로 집계한다. 수치 비교는 표본 수와 조합별 결과를 함께 공개한다.

### 제안하는 초기 통과 기준

모든 수치는 후속 평가 전에 조정·고정할 **목표 제안값**이다. 이 문서에 실측값은 없다.

| 지표 | 제안 목표 | 측정 방식 |
|---|---|---|
| 거짓 준비·성공 판정 | 고정된 부적합·미확인 사례에서 0건 | `unknown`, 누락 설정, 없는 산출물, 실패 실행을 성공 처리한 횟수 |
| 숫자 근거 추적 | 실행에 쓸 필수 설정값의 100% | 원문 필드·사용자 입력·측정 보고 중 어느 근거인지 추적. 제조사 주장 자체의 진위와는 별도 |
| 단위·기하 정확성 | 지정한 합성 형상 치수의 오차 0.01 mm 이내 | CAD 경계·재수입 결과와 명시 입력 비교. 실물 허용오차로 전용하지 않음 |
| 초보 첫 미리보기 | 지원 템플릿 작업에서 추가 질문 중앙값 1회 이하 | 준비된 목표를 받은 뒤 미리보기까지의 질문. 실제 맞춤 치수·출력 준비는 별도 측정 |
| 교정 조건 관리 | 지정한 의존성 변경 사례의 기대 상태 모두 일치 | 온도/MVS/노즐 변경과 플레이트·인필만 변경을 구분 |
| 실물 초기 반복 | 선정한 각 조합에서 최소 3회 관측 | 결과를 건별 기록. 3회 성공만으로 일반 성공률을 추정하지 않음 |

실물 치수·표면·조립의 합격 기준은 사용 목적과 측정 방법을 먼저 정한 뒤 적용한다. 임의의 공통 허용오차나 “항상 최적”을 기준으로 삼지 않는다.

## 5. 필라멘트·근거·교정

fixture의 수치는 판정 검사용 합성 데이터다. 특정 제조사의 권장 설정으로 배포하지 않는다.

| ID | 구체 입력·상황 | 기대 판정·관측 | 환경 / 준비 상태 |
|---|---|---|---|
| B10 | 정확한 material_id, 일치하는 scope, 완전한 핵심값. source.authority에는 manufacturer만 제공하고 실측 보고는 없음 | `ready_to_prepare`, `compatibility=supported`, `validation_status=unverified`. 입력된 출처 주장과 실제 원문 검증을 구분한다. | O; 현재 코드 대상 |
| B11 | 같은 브랜드의 PLA 프로필에 PLA-CF material_id를 넣음. 별도 입력에서는 라벨 식별을 ambiguous로 표시 | 명확한 제품 불일치는 `blocked/unsupported`; 모호한 식별은 `needs_input`. 문자열 유사도로 동치 처리하지 않는다. | O; 현재 코드 대상 |
| B12 | 실제 plate_type이 비어 있는 경우와, setup은 알지만 profile scope의 extruder 근거가 없는 경우 | 전자는 `needs_input`, 후자는 `needs_evidence`. 누락 필드와 필요한 다음 행동을 구분한다. | O; 현재 코드 대상 |
| B13 | nonempty inherits/include가 있는 부분 프리셋. 향후에는 누락 부모·순환 참조·동일 이름 다른 버전도 제공 | 현재는 `needs_evidence`, 자동 준비 불가. 향후 resolver는 원본 버전·필드 출처가 보존된 전체 설정만 내보내며 누락·순환을 성공 처리하지 않는다. | O; 현재 거절 경로 있음, 그래프 resolver 평가 확장 필요 |
| B14 | 출처 있는 fixture가 허용한 급지 경로와 현재 feed_mode가 불일치. 다른 경우에는 호환 근거 자체가 없음 | 명확한 불일치는 `blocked/unsupported`; 근거 누락은 `needs_evidence/unknown`. 재료 이름만으로 모든 AMS·노즐 조합을 허용하거나 금지하지 않는다. | O; 현재 scope 검사 대상. 실제 호환표는 L/N/H 별도 |
| B15 | NaN·Infinity·빈 flow ratio·서로 다른 옵션의 배열 값·미지원 확장 필드를 입력 | 비유한 값은 `blocked`, 빈 핵심값·미해결 옵션은 `needs_evidence`; 원문을 추적할 수 있다. 비핵심 확장 필드는 경고만. K·MVS를 flow ratio에 대신 넣지 않는다. | O; 현재 코드 대상 |
| B16 | 유효한 K·flow ratio·MVS 기록에 온도/MVS 변경, 노즐/핫엔드/재료 변경, 플레이트/인필만 변경을 각각 적용 | 온도/MVS 변경은 K 재검토, 하드웨어·재료 변경은 관련 측정 재검토. 플레이트·인필만 바꾼 기본 정책에서는 K를 일괄 무효화하지 않는다. 측정값 자체는 바꾸지 않는다. | O; 현재 코드 대상 |

관련 코드: [profiles.py](../print_agent/profiles.py), [test_profiles.py](../tests/test_profiles.py). 이 평가는 실제 필라멘트 성능 시험이 아니다.

## 9. 실행 순서와 결과 해석

1. 같은 버전에서 현재 오프라인 회귀 테스트를 실행하고 로그를 보존한다. 기본 명령은 `python -m unittest discover -v`다. 이 명령 하나가 위 30개 제품 사례를 모두 실행하는 것은 아니다.
2. 각 사례의 실제 기대 출력과 기록 형식을 고정한다. 아직 구현되지 않은 사례는 `not_run`과 필요한 작업을 기록한다.
3. 현장 B21을 통과한 설정·산출물을 토대로 B27·B28을 진행한다. 기기 조건을 모르면 먼저 그 정보를 수집한다.
4. 실제 LLM·자료·가격 접근이 마련된 뒤 해당 L 사례를 따로 실행한다. 공급자 이름이나 호환 표방만으로 통과를 추정하지 않는다.
5. 초보 사용자의 질문 수·중단 지점·완료 여부를 관찰한다. “빠르다” 또는 “쉽다”는 판단에는 요청 종류·사용자 경험·PC 조건을 함께 기록한다.

기준을 변경하면 벤치마크 버전을 바꾼다. 실패를 없애기 위해 어려운 조합을 결과 표에서 지우지 않는다. 지원 범위를 줄이기로 결정한 경우 이유와 제외 조건을 명시한다. 현재 통과 개수·실물 성공 횟수·라이브 연결 결과는 별도 검증 기록에서만 보고한다.
