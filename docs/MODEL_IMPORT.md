# 가진 모델 파일 점검

MakerWorld·Printables 같은 곳에서 받은 **STL·3MF 파일**을 불러와 형상을 점검하고, 서포트가 덜 필요한 **출력 방향**을 찾습니다.
왼쪽 메뉴의 **가진 모델 점검**에서 씁니다.

## 하는 일

- **원본 보관:** 원본 파일을 그대로 보관합니다. 고치거나 단순화하지 않고, 읽을 때마다 SHA-256으로 바뀌지 않았는지 확인합니다.
- **메시 정보:** 삼각형 수, 닫힌 메시인지(열린 모서리·겹친 모서리 수), 부피, 재료 사용 상한(속을 100% 채운 PLA 기준)을 보여 줍니다.
- **출력 방향 순위:** 축 방향 6가지(원래 방향, 뒤집기, 앞·뒤·왼쪽·오른쪽 면을 바닥으로)와 넓은 평면 최대 6개를 하나씩 바닥에 놓아 봅니다.
  아래 순서로 순위를 매깁니다.
  1. **45°보다 가파르게 아래를 향하고 바닥에 닿지 않는 면**(서포트가 필요할 수 있는 돌출부)이 적은 순서
  2. 바닥에 닿는 면이 넓은 순서
  3. 높이가 낮은 순서
- **방향별 점검:** 방향마다 바닥 접촉면, 세운 비율, 돌출부, 재료를 생성 모델과 같은 기준으로 점검합니다.
  벽 두께는 메시에서 재지 않으므로 이 항목은 없습니다.
- **내려받기:** 고른 방향의 **새 3MF**는 회전·이동만 한 것으로, 바닥 z = 0, 가로·세로 가운데 정렬입니다. 원본도 그대로 내려받을 수 있습니다.

## 슬라이스·출력까지 이어가기

방향을 고른 뒤 **이 방향으로 슬라이스·출력 준비**를 누르면 그 방향의 모델로 **작업**을 하나 만들고 모델 만들기 화면에서 엽니다.
- **작업 파일:** 이 방향의 3MF(앱 CAD와 같은 구조)와 STL, 생성 기록을 담습니다.
  출처에는 원본 파일 이름, SHA-256, 고른 방향(회전 행렬 포함)을 남깁니다.
- **이어지는 기능:** 앱에서 만든 모델과 같은 기능을 그대로 씁니다.
  - Bambu Studio 슬라이싱(설정 파일 묶음 또는 Studio 프로젝트)과 출력 크기 검토
  - 프린터로 보내기(기종·노즐·재료 확인 포함)
  - 결과 기록, 실패 원인, 실측 비교, 작업 기록
- **쓸 수 없는 기능:**
  - 치수 패널과 모델 수정은 이 작업에 쓸 수 없습니다. 템플릿으로 만든 모델이 아니기 때문입니다.
  - 노즐별 재점검도 없습니다. 메시의 벽 두께를 재지 않기 때문입니다.
- **확인한 것:** 로컬 Bambu Studio 02.09.01.70(합성 설정)에서 "위아래 뒤집기"와 "원래 방향" 두 작업을 실제로 슬라이스했습니다.
  각각 약 37분·7.7 g, 약 39분·7.6 g이 나왔습니다. 합성 설정은 서포트를 켜지 않습니다.

## 지원 범위

- **형식:** STL(바이너리·ASCII)과 3MF를 읽습니다. 3MF는 Bambu Studio처럼 부품을 `3D/Objects/*.model`에 따로 두는 형식도 따라갑니다.
  컴포넌트·변환 행렬·단위(마이크론~미터)를 반영하고, 출력하지 않는 개체(`printable="0"`)는 뺍니다.
- **여러 개체:** 한 판에 여러 개체가 있으면 하나로 묶어 점검합니다.
- **크기 상한:** 파일 32 MiB, 삼각형 40만 개. 이보다 크면 단순화한 뒤 다시 불러오라고 안내합니다.
  미리보기는 삼각형 6만 개까지만 고르게 골라 보여 줍니다. 점검과 내려받는 3MF에는 모든 삼각형을 씁니다.
- **단위 의심:** 어느 변이든 2,000 mm를 넘으면 단위가 잘못 저장됐을 수 있다고 알려 줍니다.

## 하지 않는 것

- 메시를 수리하거나 단순화하지 않습니다. 열린 메시는 그렇다고 알리기만 합니다.
- 벽 두께, 슬라이서 결과(서포트 양·시간·재료), 실물 출력은 확인하지 않습니다.

## API

| 요청 | 내용 |
|---|---|
| `POST /api/imports` | `{filename, content_base64}`. 원본을 보관하고 분석 결과를 돌려줍니다(201). |
| `GET /api/imports` | 최근 불러온 모델 목록 |
| `GET /api/imports/{id}` | 원본을 다시 확인해 같은 분석 결과 |
| `GET /api/imports/{id}/source` | 원본 파일 그대로 |
| `GET /api/imports/{id}/oriented?orientation=N` | N번 방향으로 놓은 3MF |
| `POST /api/imports/{id}/jobs` | `{orientation}`. 그 방향으로 작업을 만듭니다(201). 이후 기존 작업·슬라이스·전송 API를 그대로 씁니다. |

원본이나 기록이 바뀌었으면 409(`import_integrity`)를 돌려주고 결과를 내놓지 않습니다.
설치 패키지 검증은 매 릴리스마다 세 OS에서 다음을 확인합니다.
- 돌출부가 있는 STL을 불러와 원본 바이트가 같은지
- "위아래 뒤집기"를 추천하는지
- 내려받은 3MF가 닫힌 메시이고 돌출부가 없는지
- 그 방향의 작업이 만들어지고, 작업의 3MF가 슬라이싱 경로가 받는 구조인지
