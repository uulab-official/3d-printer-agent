# 전체 작업 백업과 새 폴더 복원

v0.3의 백업은 CAD 원본 기록·파일·출처·출력 메모, 저장한 필라멘트 원본·미완성
초안, 두 SQLite 저장소와 부분 파일을 함께 보존합니다. **모델 화면의 ZIP 내보내기와
전체 작업 백업은 다른 형식**입니다. 모델 ZIP은 파일 전달용이며 앱 전체를 복원할
원본 작업 기록과 필라멘트 저장소가 들어 있지 않습니다.

백업은 저장된 로컬 자료를 암호화하지 않은 ZIP으로 묶습니다. 다른 사람에게 전달하면
그 자료도 전달됩니다. 브라우저에서 아직 저장하지 않은 입력은 포함하지 않습니다.
먼저 필요한 필라멘트 작업과 출력 메모를 저장하고, 아직 저장 기능이 없는 제작안·구매
입력은 별도로 기록하세요. 페이지 종료 확인은 초안 자동 저장 기능이 아닙니다.

## 1. 저장 위치 확인과 서버 종료

화면 상단 **이 PC의 저장 위치와 복구 기록**에서 실제 절대 경로를 확인하세요.
`printer-agent doctor --data-dir "/내/데이터/폴더"`도 선택한 경로를 보여줍니다.

서버를 실행한 터미널에서 `Ctrl+C`로 종료합니다. 같은 폴더를 사용하는 서버가
실행 중이면 백업 명령이 운영체제 잠금을 확보하지 못해 오류로 끝납니다. 포트만
바꾸어 실행한 다른 서버도 같은 폴더를 사용한다면 백업할 수 없습니다.

## 2. 전체 작업 백업 만들기

실제 경로로 바꿔 실행합니다. 아래 경로는 예시이며 자동으로 선택되지 않습니다.

```bash
printer-agent backup --data-dir "/내/데이터/폴더" --output "/내/백업/작업-2026-11-14.ppa-backup.zip"
```

출력 파일의 상위 폴더는 미리 준비하세요. 백업 파일은 원본 데이터 폴더 밖에 두고,
기존 파일과 다른 이름을 사용합니다. 기존 백업을 덮어쓰는 옵션은 없습니다.
`--data-dir`를 생략하면 일반 실행과 같은 경로 선택 규칙을 사용하므로, 여러 폴더를
운영한다면 명시하는 편이 분명합니다.

명령은 전체 파일의 상대 경로·크기·SHA-256을 기록하고 작성한 아카이브를 다시 검사한
뒤 완성된 파일을 공개합니다. 성공 JSON의 `status`는 `created`이며 `archive_path`,
`archive_sha256`, `archive_bytes`, `file_count`, `total_bytes`를 확인할 수 있습니다.
파일 바이트는 그대로 보존하며 정상 작업으로 다시 생성하거나 해시 근거를 새로
인증하지 않습니다. 실행 잠금 파일 `.printer-agent.lock`은 백업하지 않습니다.

## 3. 복원 전에 검사하기

```bash
printer-agent backup-info --archive "/내/백업/작업-2026-11-14.ppa-backup.zip"
```

`status: verified`는 아카이브의 목록·크기·SHA-256·ZIP 구조가 일치한다는 뜻입니다.
이 검사는 파일을 풀거나 CAD·Studio를 실행하지 않고 저장소도 열지 않습니다.
백업을 만든 뒤 파일이 바뀌거나 잘렸다면 실패합니다.

**바이트 무결성과 앱 자료의 정상 여부는 별개입니다.** 이미 손상된 파일도 원본대로
백업할 수 있습니다. 따라서 `verified`만으로 모든 모델 다운로드나 필라멘트 저장소가
정상이라고 판단하지 않습니다. 제작자 인증, 서명 또는 실제 출력 품질 판정도 아닙니다.

## 4. 새 폴더로 복원하기

```bash
printer-agent restore --archive "/내/백업/작업-2026-11-14.ppa-backup.zip" --destination "/내/복원된-작업"
```

목적지는 **아직 존재하지 않는 폴더**여야 합니다. 비어 있는 기존 폴더, 심볼릭 링크,
기존 데이터와의 병합도 허용하지 않습니다. 목적지의 상위 폴더는 미리 준비하세요.

먼저 비공개 임시 폴더에 전체 자료를 검증하고, 저장소의 호환성을 읽기 전용으로
확인한 뒤 완성된 폴더를 기존 경로를 대체하지 않는 방식으로 공개합니다. 검사 실패나
목적지 충돌이 발생하면 기존 자료를 유지합니다. 실패 중 만들어진 임시 자료만 정리하며
원본과 다른 사람의 폴더를 지우지 않습니다. 강제 종료 후 남은 임시 폴더는 성공적으로
복원된 폴더라고 표시하지 않습니다.

SQLite의 WAL 형식은 검사 중에도 보조 파일을 만들 수 있으므로, 호환성 확인에는
별도의 임시 복사본을 사용합니다. 커밋된 WAL 내용까지 읽고, 검증한 복원 파일의
바이트와 목록은 그대로 남깁니다. 이 경우 데이터베이스와 WAL을 복사할 임시 공간이
추가로 필요합니다.

성공 JSON의 `status`는 `restored`이며 `data_dir`가 복원된 절대 경로입니다.
복원은 기본 저장 위치를 바꾸거나 앱을 자동 실행하지 않습니다. 다음처럼 따로 확인합니다.

```bash
printer-agent doctor --data-dir "/내/복원된-작업"
printer-agent --data-dir "/내/복원된-작업"
```

필라멘트 원본 저장소의 알 수 없는 구조나 손상은 복원 공개 전에 거절합니다.
작업 이력 SQLite는 파생 색인이므로 기존의 손상 원본 보존·재구성 경로가 적용될 수
있습니다. 복원 명령 자체는 작업 파일을 수리하거나 중단된 CAD·슬라이싱을 재실행하지
않습니다. 앱을 실행하면 기존 시작 복구 규칙이 적용됩니다.

## 업데이트와 되돌리기

1. 편집 내용을 저장하고 서버를 종료합니다.
2. 전체 백업을 만들고 `backup-info`로 검사합니다.
3. 검증할 새 버전을 별도 Python 3.12 가상환경에 설치합니다.
4. 백업을 새 폴더에 복원하고 그 경로를 명시해 `doctor`와 앱을 실행합니다.
5. 필요한 작업과 다운로드를 확인한 뒤 사용할 버전과 데이터 폴더를 선택합니다.

기존 프로그램 환경과 원본 폴더를 남기면 새 환경을 종료하고 원래 환경·폴더로 돌아갈
수 있습니다. 새 버전이 수정한 데이터의 이전 버전 호환성까지 가정하지 않습니다.
이 절차는 자동 업데이트나 자동 롤백 서비스가 아닙니다.

## 오류와 범위

정상 명령은 종료 코드 0, 알려진 백업·IO·호환성 오류는 JSON과 종료 코드 1,
누락되거나 맞지 않는 명령 인자는 종료 코드 2를 반환합니다. 실패한 복원을 해결하기
위해 기존 데이터 폴더를 지우거나 파일 이름을 임의로 바꿀 필요는 없습니다.

| 제한 | 값·동작 |
|---|---|
| 파일 수 | 최대 20,000개 |
| 파일 하나 | 최대 512 MiB |
| 전체 원본 크기 | 최대 4 GiB |
| manifest | 최대 8 MiB, 형식 버전 1 |
| 파일 종류 | 일반 파일만; 링크·장치·특수 파일 거절 |
| 경로 | 상대 경로; 탈출·드라이브·UNC·Windows 예약 이름·대소문자/유니코드 충돌 거절 |
| ZIP 압축 | STORED 또는 DEFLATE; 암호화·다른 코덱 거절 |
| 파일 속성 | 파일 내용과 경로 보존; OS 권한·소유자·ACL·확장 속성의 이식 기능은 아님 |

한도를 넘는 자료에는 기존 전체 폴더 복사 방법을 사용할 수 있지만, 그것을 이 백업
형식의 검증 통과로 계산하지 않습니다. 파일시스템이 기존 경로를 대체하지 않는 원자적
공개 기능을 지원하지 않으면 오류로 종료하며 덮어쓰는 방식으로 대체하지 않습니다.
실제 플랫폼별 검증 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록합니다.
