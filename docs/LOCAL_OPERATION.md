# 로컬 설치와 운영

v0.3의 지원 실행 경로는 Python 3.12 가상환경과 자신의 PC에 바인딩된
`127.0.0.1` 서버입니다. CAD와 파일 처리는 해당 PC에서 수행합니다. 설치 패키지,
브라우저 사용 흐름, native Bambu, 실제 프린터는 각각 별도로 검증합니다.
실제 관측한 플랫폼과 커밋은 [VERIFICATION.md](VERIFICATION.md)에 기록합니다.

## 설치할 버전 확인

소스 설치는 README의 가상환경 절차를 사용하세요. 게시된 패키지는
[GitHub Releases](https://github.com/uulab-official/3d-printer-agent/releases)에서 받습니다.
같은 릴리스의 SHA256SUMS·영수증과 wheel 해시를 대조하는 절차는
[릴리스 안내](RELEASES.md)에 있습니다. 개별 커밋의 검증 진행 상황은
[Installed desktop package qualification](https://github.com/uulab-official/3d-printer-agent/actions/workflows/package-qualification.yml)에서
사용할 커밋과 세 운영체제의 결과를 확인합니다. `installable-wheel-<commit>`
산출물에는 같은 실행의 wheel, `wheel-receipt.json`, `SHA256SUMS`가 있습니다.
플랫폼별 결과에는 실제 운영체제·아키텍처·Python·CadQuery 버전과 검사 결과가 남습니다.
workflow가 존재하거나 wheel 빌드만 성공한 것을 전체 설치 성공으로 해석하지 않습니다.

가상환경을 활성화한 뒤 내려받은 파일을 설치하는 예시입니다.

```bash
python -m pip install ./3d_printer_agent_local-0.3.0-py3-none-any.whl
printer-agent --version
printer-agent doctor
printer-agent
```

PowerShell에서도 가상환경의 `python.exe -m pip`와 `printer-agent.exe`를 사용할
수 있습니다. `python -m print_agent` 진입점도 같은 기능을 제공합니다. wheel은
앱 코드와 UI를 포함하고, Python/CAD 패키지 의존성은 pip가 설치합니다. 오프라인
의존성 묶음, 서명된 앱 설치 프로그램, 자동 업데이트 서비스는 제공하지 않습니다.
Actions 산출물의 보관 기간은 현재 14일이며 GitHub Release 자산과는 다릅니다.

Ubuntu 24.04의 실제 설치 검증은 시스템 라이브러리 `libgl1`을 준비한 뒤 실행합니다.
가상환경이나 pip가 시스템 패키지를 설치하지 않으므로 해당 환경에서는 먼저 실행하세요.

```bash
sudo apt-get update
sudo apt-get install -y libgl1
```

다른 Linux 배포판의 패키지 이름이나 기본 설치 상태는 이 검사로 확인하지 않았습니다.

## 데이터가 저장되는 위치

시작 로그와 화면 상단의 **저장 위치**에는 실제 절대 경로와 선택 이유가 표시됩니다.
경로를 선택하는 순서는 다음과 같습니다.

| 우선순위 | 조건 | 동작 |
|---|---|---|
| 1 | `--data-dir` 지정 | 지정한 폴더 사용 |
| 2 | 비어 있지 않은 `PPA_DATA_DIR` | 환경 변수의 폴더 사용 |
| 3 | 현재 폴더에 기존 앱 자료가 있는 `./data` | 기존 자료를 그대로 사용하고 legacy 경로로 표시 |
| 4 | 위 조건이 없음 | 운영체제의 고정 사용자 데이터 폴더 사용 |

| 운영체제 | 새 설치의 기본 위치 |
|---|---|
| macOS | `~/Library/Application Support/3DPrinterAgent` |
| Windows | `%LOCALAPPDATA%\3DPrinterAgent`; 해당 값이 없으면 사용자 홈 아래 `AppData\Local\3DPrinterAgent` |
| Linux | 절대 경로인 `$XDG_DATA_HOME/3d-printer-agent`, 또는 `~/.local/share/3d-printer-agent` |

legacy 판정은 기존 `history.sqlite3`, `profile-workspaces.sqlite3` 또는 유효한
작업 ID 폴더 안의 `job.json`이 있을 때 적용합니다. 빈 `data` 폴더만으로 새 기본
경로를 가리지 않습니다. 기존 폴더는 자동 이동하지 않습니다. legacy 자료를 다른
실행 폴더에서도 계속 사용하려면 그 경로를 명시하세요.

```bash
printer-agent --data-dir "/absolute/path/to/existing/data"
printer-agent doctor --data-dir "/absolute/path/to/existing/data"
```

같은 데이터 폴더는 한 서버만 사용합니다. 포트를 바꾸어도 같은 폴더를 동시에
열 수 없습니다. 운영체제가 실행 중인 프로세스의 잠금을 관리하므로 서버가 끝나면
해제됩니다. 폴더에 잠금 파일이 남아 있는 것 자체는 실행 중이라는 뜻이 아닙니다.
서로 다른 데이터 폴더는 독립적인 작업 공간입니다.

## 연결이 끊겼을 때

서버를 다시 실행한 뒤 화면의 **다시 연결**을 누릅니다. 페이지를 새로 고치지 않고
같은 데이터 폴더의 현재 치수·요청·재료 편집·받아 둔 결과를 유지하며 새 세션을 받습니다. 모델 생성,
슬라이싱, 저장, 출력 결과 등록을 자동 반복하지 않습니다. 통신이 끊기기 전에
서버에서 처리했을 수 있으므로 작업 기록이나 저장된 필라멘트 작업을 먼저 확인합니다.

재연결 이전에 보낸 요청의 응답이 늦게 도착해도 새 연결의 화면에 적용하지 않습니다.
이때 서버 작업이 취소됐다고 간주하지 않으며, 기록에서 결과를 직접 확인할 수 있습니다.
서버가 다른 데이터 폴더로 바뀌었다면 치수·요청·재료 편집 내용은 유지하고 이전 폴더의
결과·다운로드·저장본 연결은 해제합니다. 화면에 이전 경로와 현재 경로를 알려주며,
필라멘트 편집 내용은 새 위치에 새 작업으로 저장할 수 있습니다.
저장하지 않은 출력 결과 메모는 원래 작업과 경로가 적힌 별도 보관 영역에 남습니다.
새 모델에 자동으로 붙이지 않으며, 메모를 옮긴 뒤 보관 해제를 선택할 수 있습니다.
이 보관 영역도 현재 브라우저 메모리이므로 페이지 종료 전에 필요한 내용을 저장하세요.

다른 작업이 CAD 또는 슬라이서를 사용 중이면 `resource_busy` 응답으로 알려주며
새 CAD 작업을 대기열에 쌓지 않습니다. 완료 후 직접 다시 시도할 수 있습니다.
모델 서버는 비압축 JSON 응답 본문 100,000바이트와 전체 대기 시간 60초 제한을 적용합니다.
압축된 응답은 본문을 읽기 전에 거절하여 해제 과정에서 크기 제한을 넘지 않게 합니다.
시간 초과는 모델 서버의 외부 계산이 취소됐다는 뜻이 아닙니다.

모델 치수·요청·슬라이서 입력·출력 메모에 저장하지 않은 변경이 있으면 이력 열기,
템플릿 교체 또는 초기화 전에 확인합니다. 취소하면 현재 입력을 유지합니다. 페이지를
벗어날 때에도 저장하지 않은 작업을 확인하지만, 브라우저의 종료 확인 정책이나 강제
종료까지 제어하지는 않습니다. 이 기능은 브라우저 초안의 자동 영구 저장이 아닙니다.
구매 비교의 입력과 진행 중인 비교도 페이지 종료 확인에 포함합니다. 비교 결과를
계산해도 입력이 저장된 것으로 표시하지 않습니다. 비교 중에는 기존처럼 가격·중량·
배송·통화 입력을 잠그며, 완료 후 조건을 바꾸면 이전 결과를 해제합니다.

## 중단된 작업과 이력 복구

서버는 데이터 폴더의 독점 사용을 확보한 다음 저장된 작업 파일을 읽어 이력 색인을
맞춥니다. 생성 도중 끝난 작업은 `interrupted`로 기록하고, 입력해 둔 형상 요청과
부분 파일을 보존합니다. 부분 파일은 검증된 다운로드로 제공하지 않습니다.
**작업 기록 → 기록 보기 → 저장된 치수로 다시 준비**는 편집 가능한 제작안만
복원하며 모델 생성을 자동 실행하지 않습니다.

완료되지 않은 슬라이싱도 별도 중단 상태로 기록합니다. 기존 CAD는 유지하지만
이전 슬라이스를 새 요청의 결과로 제공하지 않습니다. 읽을 수 없는 개별 작업은
이력에 진단 상태로 남기고 원본 파일을 덮어쓰지 않습니다. 정상적인 다른 작업은
계속 열 수 있습니다. 오래된 기록은 **이전 기록 더 보기**로 순서대로 불러옵니다.

`job.json`은 CAD 작업의 기록이고 `history.sqlite3`는 탐색을 위한 파생 색인입니다.
색인이 없거나 오래됐으면 작업 파일을 기준으로 다시 구성합니다. 색인 파일 자체가
손상됐으면 원본 바이트를 별도 백업으로 보존한 뒤 독점 시작 절차에서 재구성합니다.
`profile-workspaces.sqlite3`는 필라멘트 작업의 원본 저장소이므로 같은 방식으로
삭제하거나 재구성하지 않습니다. 그 파일이 손상됐다면 저장해 둔 백업이 필요합니다.
v0.3은 두 저장소를 쓰기 전에 읽기 전용으로 호환성을 확인합니다. 알 수 없는 테이블·
열 구조나 원본 저장소의 손상 때문에 비어 있는 작업 화면을 새로 만드는 대신,
시작을 중단하고 기존 파일을 그대로 남깁니다.

## 다운로드가 차단됐을 때

새 작업은 생성 파일과 manifest의 크기·SHA-256을 작업 기록에 보관합니다. 파일과
ZIP 묶음을 내려받을 때 실제 읽은 바이트를 대조하고, 확인한 바이트 그대로 응답합니다.
파일이 없어졌거나 바뀌면 HTTP 409의 `artifact_integrity` 오류로 알려줍니다.
원본 파일을 자동 삭제하거나 변경하지 않습니다. 이전 백업과 비교하거나 저장된
요청으로 새 작업을 생성하세요.

이전 버전의 작업은 기존 manifest와 기록에 있는 근거만 사용합니다. 원래 manifest
바이트 해시가 없는 자료에 새 해시를 붙여 과거 원본이 인증됐다고 주장하지 않습니다.
해시 비교는 저장된 자료의 일관성 확인이며 제작자 인증, 실물 품질 또는 출력 가능
판정을 대신하지 않습니다.

## 진단, 백업과 업데이트

`printer-agent doctor`는 앱·Python·운영체제, 필요한 모듈과 UI 자산, 선택한 경로,
저장소 상태를 JSON으로 표시합니다. 필수 검사에 실패하면 종료 코드 1입니다.
선택 기능인 LLM이나 Bambu Studio가 설정되지 않아도 로컬 CAD 준비 판정은 가능합니다.
일반 진단은 native 프로그램을 실행하지 않습니다. `doctor --probe-slicer`를 명시한
경우에만 설정된 Bambu Studio의 도움말로 기능을 확인합니다. API 키는 출력하지 않습니다.
알 수 없는 저장소 스키마는 파일을 그대로 보존하고 원인을 확인해야 하는 상태로
표시하며, 재시작하면 자동 복구되는 손상 색인과 구분합니다.

업데이트 전에는 편집 내용을 저장하고 서버를 종료한 뒤 `printer-agent backup`으로
**화면에서 확인한 데이터 폴더 전체**를 보관합니다. `backup-info`로 검사하고 새 버전의
가상환경에서 아직 존재하지 않는 폴더로 `restore`한 뒤 경로를 명시해 확인하세요.
[전체 명령·한도·오류와 되돌리기 절차](BACKUP_RESTORE.md)를 따릅니다.

백업은 모델 기록과 부분 파일, 필라멘트 원본·미완성 초안, 두 SQLite 저장소를 함께
보관합니다. 기존 파일·폴더를 덮어쓰지 않으며, 브라우저에서 저장하지 않은 입력은
포함하지 않습니다. 모델 내보내기 ZIP으로 전체 작업을 복원할 수는 없습니다.
백업 명령의 한도를 넘는 자료는 서버가 종료된 상태에서 전체 폴더를 별도 위치에
복사할 수 있지만, 그 복사가 검증된 백업 형식이라는 뜻은 아닙니다.

새 환경의 `--version`과 `doctor --data-dir ...`를 확인하고 복원한 경로로 실행합니다.
원래 환경과 데이터 폴더를 유지하면 비교하고 돌아갈 수 있습니다. 새 버전이 수정한
자료를 이전 프로그램으로 읽는 호환성까지 가정하지 않습니다.

## 구현 근거

설계와 실제 결과는 [구현 계약](CONTRACTS.md), [상태](STATUS.md),
[검증 기록](VERIFICATION.md)을 참조하세요. OS 잠금과 HTTP 스트리밍 구현은
[Python 3.12 fcntl](https://docs.python.org/3.12/library/fcntl.html),
[Python 3.12 msvcrt](https://docs.python.org/3.12/library/msvcrt.html),
[HTTPX 비동기 스트리밍](https://www.python-httpx.org/async/),
[HTTPX timeout 의미](https://www.python-httpx.org/advanced/timeouts/)에 따릅니다.
설치 검사 runner 선택은 [GitHub 공식 runner 문서](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)를
기준으로 하며, 실제 실행 보고서의 운영체제와 아키텍처를 최종 관측값으로 기록합니다.
