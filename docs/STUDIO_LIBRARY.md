# Studio 설정 보관함

CAD를 만들기 전에도 Studio 설정에 이름을 붙여 보관하고 다음에 다시 열 수 있습니다. 가져온 원본, 적용한 변경값과 미완성 입력을 구분해 저장합니다. 기존 버전에서 가져온 원본과 생성한 변경 기록도 목록에서 찾을 수 있습니다.

## 저장하고 다시 사용하기

1. 지원하는 Studio `.3mf`를 가져오고 기록된 프린터·노즐·플레이트·재료를 확인한 뒤 후보를 선택합니다.
2. 원본 설정을 그대로 보관하거나 [여섯 설정 편집](STUDIO_SETTINGS.md)에서 값을 입력합니다. 완성하지 못한 숫자도 초안으로 저장할 수 있습니다.
3. 보관함에 이름을 입력하고 저장합니다. 다른 설정 조합을 남기려면 복사본으로 저장합니다. CAD 작업은 필요하지 않습니다. 같은 화면에서 새 저장본을 목록에 표시하려면 **목록 새로고침**을 누르세요.
4. 앱을 다시 열었을 때 보관함에서 저장한 설정을 선택해 엽니다. 서버가 원본과 변경 기록을 다시 검사한 뒤 후보로 보여 줍니다.
5. 후보를 명시적으로 선택하면 저장된 입력을 가져옵니다. 미완성 초안은 이어서 수정하고 차이를 검토·적용합니다. 사용할 CAD를 생성한 뒤 새 프로젝트를 준비합니다.

저장한 이름은 사용자의 구분용 메모입니다. 필라멘트 제품 ID, 제조사 권장값이나 출력 성공 인증으로 사용하지 않습니다. 이름을 바꾸어도 원본과 변경 기록의 식별 정보는 바뀌지 않습니다.

## 세 가지 목록

| 목록 | 보이는 내용 | 다시 열 때 |
|---|---|---|
| 저장한 설정 | 이름, 저장 정보, 원본·변경 기록 참조, 초안 유무 | 원본과 선택한 변경 기록을 재검증하고 저장한 입력을 후보로 표시 |
| 가져온 원본 | 이전 버전에서 가져온 파일을 포함한 원본 기록 | 원래 파일의 바이트와 설정을 다시 검사 |
| 설정 변경 기록 | 이전에 검토·적용한 변경 기록 | 원본에서 변경값을 다시 계산해 확인 |

목록은 저장 당시의 정보를 보여 줍니다. 목록에 나타났다는 것만으로 현재 파일이 정상이라고 판단하지 않으며, 열 때 검사합니다. 같은 이름의 파일도 각각 원본 ID가 있으므로 기록된 조건과 식별 정보를 함께 확인하세요. 다음 페이지를 불러와 나머지 기록을 찾을 수 있습니다. 목록 갱신이나 항목 선택만으로 현재 설정이 적용되지는 않습니다.

## 미완성 입력과 저장 충돌

보관함은 여섯 항목의 문자열을 그대로 저장합니다. `1.`, 앞뒤 공백, 잘못 붙여 넣은 값도 각 항목 512자, 전체 저장 입력 16 KiB 이내라면 보관할 수 있습니다. 숫자를 검토·적용하는 기존 32자 제한과 값 범위는 그대로입니다. **저장이 끝났다는 것과 슬라이싱에 적용할 값이 유효하다는 것은 별개의 상태**입니다.

저장 중 새로 입력한 내용은 저장 응답으로 바뀌지 않습니다. 제출했던 내용이 저장됐더라도 그 뒤에 작성한 내용은 다시 저장해야 합니다. 다른 탭에서 같은 항목을 수정하면 오래된 탭의 저장·삭제를 거절합니다. 현재 초안을 복사본으로 저장하거나 저장된 최신 항목을 다시 열 수 있습니다.

다른 항목을 여는 동안 새로 편집하거나 저장 위치·연결이 바뀌면 늦은 응답을 적용하지 않습니다. 후보 교체를 취소하면 기존 입력을 유지합니다. 현재 검토 결과나 준비 파일, 실행 허용 상태를 보관함에 저장하지 않으므로 다시 사용하려면 현재 조건으로 검토하고 준비해야 합니다.

## 삭제·손상·백업

보관함의 삭제는 이름 붙인 항목만 제거합니다. 가져온 원본, 변경 기록, 기존 CAD 작업과 준비 파일은 유지됩니다. 삭제 후 **목록 새로고침**을 누르면 목록을 다시 읽습니다. 원본·변경 기록 목록에서 계속 찾을 수 있습니다.

손상된 항목 하나 때문에 다른 정상 항목의 목록이 사라지지 않습니다. 원본이나 변경 기록이 없거나 달라졌으면 열기 오류를 표시하고 현재 입력을 유지합니다. 편집 기록이 손상됐을 때 원본 설정으로 바꾸어 적용하지 않습니다.

저장한 보관함은 `studio-workspaces.sqlite3`에 들어 있으며 [전체 백업](BACKUP_RESTORE.md)에 원본·변경 기록과 함께 포함됩니다. 새 폴더로 복원한 뒤 앱에서 다시 목록을 열 수 있습니다. 복원된 설정으로 현재 CAD를 새로 준비하며, 과거 경로의 실행 계획은 재사용하지 않습니다. 브라우저에서 저장하지 않은 내용은 백업에 들어가지 않습니다.

이 데이터베이스는 사용자가 저장한 원본 정보입니다. 구조가 손상되거나 다른 형식이면 자동 재생성하지 않습니다. 앱을 종료하고 파일을 보존한 뒤 확인된 백업을 새 폴더에 복원하세요. 기존 버전의 데이터 폴더는 보관함 파일이 없어도 열 수 있으며 앱이 새 보관함을 초기화합니다. 기존 원본·변경 기록을 이동하거나 고쳐 쓰지 않습니다.

## API와 저장 형식

| 요청 | 응답·동작 |
|---|---|
| `GET /api/studio-library?kind=workspaces` | 이름 붙인 설정의 기록된 메타데이터 |
| 같은 경로의 `kind=sources` / `kind=revisions` | 기존 원본 / 변경 기록의 메타데이터 |
| `POST /api/studio-workspaces` | `{title, snapshot}`으로 새 항목 생성, 201 |
| `GET /api/studio-workspaces/{id}` | `{workspace, source, settings_revision, editor}` 재검증 결과 |
| `PUT /api/studio-workspaces/{id}` | `{title, snapshot, expected_revision}` 조건부 저장 |
| `DELETE /api/studio-workspaces/{id}` | `{expected_revision}` 조건부 삭제, 204 |

목록의 `limit`은 1–100, 기본 25이며 `before`는 이전 응답의 `next_cursor`입니다. ID 내림차순의 배타적 커서를 사용하며 날짜순이라고 보장하지 않습니다. 목록을 위해 원본 ZIP 전체를 풀지 않으며 페이지의 크기가 제한된 메타데이터만 읽습니다. `metadata_status: recorded`는 저장된 메타데이터를 읽었다는 뜻이고 `unreadable`은 해당 메타데이터를 읽지 못했다는 뜻입니다. 목록에는 초안 원문을 포함하지 않습니다.

`snapshot`에는 `schema_version: 1`, `source_id`, 선택적인 `settings_revision_id`(없으면 `null`), `source_sha256`, `settings_sha256`, `effective_settings_sha256`, 선택적인 `draft_values`(없으면 `null`)만 들어갑니다. 초안이 있으면 여섯 공개 필드의 문자열을 모두 포함합니다. 원본 선택의 유효 설정 해시는 원본 설정 해시와 같습니다. 서버는 참조와 해시를 실제 원본·재계산한 변경 기록과 대조하며 임의의 검토 결과를 받지 않습니다.

이름은 앞뒤 공백을 제거한 1–120자입니다. 저장 버전은 양의 안전한 정수로 제한합니다. 오래된 저장 버전은 409, 저장된 항목 또는 참조 손상은 `studio_workspace_integrity` 코드의 409, 없는 항목은 404, 잘못된 새 입력은 422입니다. 변경 요청에는 기존 로컬 세션 토큰과 출처 검사가 적용됩니다.
