# Studio 프로젝트의 설정으로 새 CAD 준비하기

사용하던 Bambu Studio `.3mf` 프로젝트 하나에서 **전역 출력 설정**을 읽고, 이 앱에서 생성한 현재 CAD에 적용합니다. 프린터·프로세스·필라멘트 JSON을 각각 찾지 않아도 됩니다. 가져온 원본은 별도로 보관하며, 준비된 프로젝트와 실제 슬라이싱 결과를 구분합니다.

## 사용 순서

1. 모델 화면의 **프로젝트 하나로 출력 설정 준비**에서 **프로젝트 .3mf 가져오기**를 누릅니다. CAD를 만들기 전에도 설정을 확인할 수 있습니다.
2. **확인한 후보 · 아직 적용하지 않았습니다**에서 프린터, 노즐, 플레이트, 필라멘트, 프로세스를 확인합니다. 이 값은 파일의 기록이며 현재 프린터에 장착된 재료나 노즐을 측정한 결과는 아닙니다.
3. 지원되는 후보의 **이 프로젝트 설정 선택**을 누릅니다. 기존 설정을 유지하려면 **후보 취소 · 기존 입력 유지**를 선택하세요. 이전 수동 JSON과 별도의 재료 편집 내용은 유지됩니다.
4. 현재 CAD를 생성하고 **현재 CAD에 설정 담기**를 실행합니다. 원본 모델은 가져오지 않으며, 현재 앱 CAD와 가져온 전역 설정을 합친 `prepared-project.3mf`를 만듭니다.
5. **설정 포함 3MF 다운로드**로 준비된 프로젝트를 받습니다. 파일 준비와 다운로드에는 Studio 설치가 필요하지 않습니다.
6. 앱에서 직접 슬라이싱하려면 지원되는 Studio 실행 파일을 설정하고, 준비 결과를 확인한 뒤 **이 프로젝트로 슬라이싱**을 명시적으로 누릅니다. 이 앱은 프린터로 작업을 전송하지 않습니다.

현재 지원하는 CAD는 수납 트레이, 열린 케이블 받침, 원형 인셋 프레임입니다. 가져온 프로젝트 안의 외부 모델을 수정하거나 MakerWorld 모델을 리믹스하는 기능은 포함하지 않습니다. 별도의 재료 검토 보고서를 이 프로젝트의 네이티브 설정으로 자동 변환하지도 않습니다.

## 지원 범위

| 항목 | 현재 범위 |
|---|---|
| 저장한 프로젝트 버전 | `BambuStudio-02.09.01.70`, 3MF 형식 `1`, 설정 버전 `02.09.01.70` |
| 프린터 기술 | FFF |
| 재료·노즐·활성 익스트루더 | 각각 하나 |
| 플레이트 | 프로젝트의 명시적 native 값과 해당 베드 온도 |
| 설정 원본 | `Metadata/project_settings.config`의 병합된 전역 설정 |
| 실행 프로그램 | 서버가 발견하거나 `PPA_BAMBU_PATH`로 지정한 실행 파일의 정확한 지원 버전 |
| 실행 전 확인 | 원본·CAD·파생 프로젝트·준비 기록의 해시와 고정 인수 재검사 |

지원 버전이 다르거나 여러 재료·노즐·익스트루더가 있는 유효한 프로젝트는 이유를 표시합니다. 지원 표시를 얻기 위해 원본의 버전이나 producer 이름을 고치지 마세요. 다른 버전 및 실제 프린터 구성은 별도 검증이 필요합니다.

Studio의 프로젝트 설정은 `from: "project"`인 병합 설정입니다. 이를 `system`이나 `filament`로 바꾸거나 상속 표시를 지우지 않습니다. 기존 전체 JSON 경로는 고급 입력에서 계속 사용할 수 있습니다.

## 정확히 옮기는 내용

설정 JSON의 UTF-8 바이트와 알려지지 않은 전역 키까지 그대로 보존합니다. 현재 CAD의 메시 좌표와 연결 관계를 유지하고, 지원되는 한 객체·한 플레이트 구조를 만듭니다. 준비 기록에는 원본 파일 SHA-256, 설정 SHA-256, 현재 CAD SHA-256, 파생 프로젝트 SHA-256과 크기가 들어갑니다.

원본 모델, 객체별·플레이트별 설정 덮어쓰기, 페인팅, 미리보기 이미지, 이전 G-code, 높이별 코드와 원본 객체 구성은 옮기지 않습니다. 호스트 후처리 프로그램이 들어 있는 설정은 사용할 수 없습니다. 준비 화면과 기록에서 이 범위를 확인할 수 있습니다.

지원 Studio는 프로젝트의 Application 표시로 로딩 경로를 구분합니다. 실제 네이티브 실험에서 확인한 경로에 따라 **원본에 실제로 기록된 지원 버전 표시**를 유지하고, `3DPrinterAgent:ModifiedBy`, 원본 해시, 새 CAD 해시를 별도로 기록합니다. 이 표시는 형식 호환 정보이며 발행자 인증이나 새 모델을 Studio에서 설계했다는 주장이 아닙니다.

## 준비 파일과 슬라이싱 파일

| 결과 | 확인한 내용 |
|---|---|
| 원본 `.3mf` | 가져온 원래 바이트와 기록된 설정 |
| 준비된 프로젝트 `prepared_three_mf` | 현재 CAD와 원본 전역 설정을 합친 별도 파일, 파일 해시 검증 |
| 네이티브 슬라이싱 결과 `sliced_three_mf` | 실제 실행의 새 출력, ZIP·G-code·현재 CAD 메시·핵심 설정·전체 설정 차이 검사 |
| 실물 출력 결과 | 사용자가 별도로 보고한 결과 |

슬라이싱 시 자동 배치로 `wipe_tower_x`, `wipe_tower_y`가 달라질 수 있고, 검증한 버전은 빈 `upward_compatible_machine`을 추가할 수 있습니다. 준비 파일의 설정은 원본과 동일하며, 네이티브 출력의 변경은 별도 비교에 기록합니다. 검증한 정규화 이외의 변화는 핵심 설정이 맞더라도 `needs_review`로 표시합니다.

새 파일 선택, CAD 변경, 재연결 또는 취소 뒤에 도착한 오래된 결과는 현재 작업을 덮어쓰지 않습니다. 새 준비를 시작하면 이전 준비·슬라이싱 다운로드를 현재 결과에서 해제합니다. 실행 실패 때도 확인된 준비 파일은 별도로 받을 수 있으며, 손상된 파일은 다운로드하지 않습니다.

## 기록·재연결·백업

원본은 데이터 폴더의 `studio-projects/<서버가 만든 ID>/`에 보관합니다. 이름으로 경로를 만들지 않습니다. 읽거나 내려받을 때마다 크기·해시·검사 결과를 다시 확인하며 기존 원본을 교체하지 않습니다.

작업 이력은 적용한 원본, 설정 요약, 준비 기록과 결과를 보존합니다. 이력을 열었다고 실행을 자동으로 허용하지 않습니다. 원본을 다시 확인하고 현재 작업으로 새로 준비해야 합니다. 재연결도 가져오기·준비·실행을 자동 재전송하지 않으며, 저장 위치가 바뀌면 원본 ID를 다시 확인해야 합니다.

[전체 백업과 복원](BACKUP_RESTORE.md)에 원본, 준비 파일과 기록도 함께 들어갑니다. 다른 폴더로 복원한 뒤에도 동일한 원본 ID로 확인하고 다운로드할 수 있습니다. 기록에 남은 과거 실행 경로를 재사용하지 않고 새 준비를 수행합니다.

## 입력 크기와 API

압축 파일 16 MiB, 전체 압축 해제 128 MiB, 항목 4,096개, 설정 JSON과 루트 모델 XML 각각 2 MiB까지 받습니다. 일반 ZIP의 실제 압축 해제 크기·CRC·로컬/중앙 목록을 검사하며 ZIP64·분할 ZIP, 중복/탈출 경로, 링크·특수 파일·암호화·지원하지 않는 압축 및 숨겨진 데이터는 받지 않습니다. JSON 중복 키·비유한 숫자·과도한 중첩, XML DTD·엔티티 선언도 거부합니다. 잘못된 파일을 가져오다 실패해도 이미 적용한 입력을 바꾸지 않습니다.

- `POST /api/studio-projects/import`: `{filename, content_base64}`. 이 경로만 전체 JSON 24 MiB를 허용합니다.
- `GET /api/studio-projects/{source_id}`: 원본을 재검사하고 요약을 반환합니다. 원문 설정은 일반 응답에서 제외합니다.
- `GET /api/studio-projects/{source_id}/archive`: 검증한 원래 파일을 받습니다.
- `POST /api/slice`: `{job_id, studio_project_id, execute}`. `config_bundle`과 `studio_project_id` 중 정확히 하나만 지정합니다. 기존 요청 제한 8 MiB는 유지합니다.

변경 요청에는 기존 로컬 세션·출처 검사가 적용됩니다. 브라우저가 실행 파일 경로, 임의 명령이나 실행 계획을 전달하는 API는 없습니다.

실제 검증 커밋·실행·패키지 바이트는 [검증 기록](VERIFICATION.md)을 확인하세요. [Bambu Studio 연동 설명](BAMBU_STUDIO.md)은 기존 전체 JSON 경로와 upstream 근거도 설명합니다.

## v0.4.0에서 실제 확인한 범위

[공개 릴리스](https://github.com/uulab-official/3d-printer-agent/releases/tag/v0.4.0)는
소스 `501a512`에서 일반 CI, 세 운영체제의 같은 wheel 설치 검증과 Linux native
검증을 통과한 패키지입니다. 데스크톱·모바일 화면 크기의 실제 Chromium에서
가져오기, 명시적 선택, 실제 CAD 준비·다운로드, 이력과 서버 재연결을 확인했습니다.

[Native 실행](https://github.com/uulab-official/3d-printer-agent/actions/runs/43599424530)은
합성 단일 필라멘트 설정으로 실제 Studio가 만든 큐브 프로젝트를 원본으로 사용하고,
다른 케이블 CAD를 새로 준비해 슬라이싱했습니다. 원본의 전역 설정 612개와 준비
파일의 설정 바이트가 같고, native 출력의 새 메시와 전체 설정 차이를 검사했습니다.
GUI에서 저장한 사용자 프로젝트, 제조사 프리셋, 다른 Studio 버전·운영체제의 native
실행과 실물 출력은 이 검사로 검증됐다고 주장하지 않습니다.
