# 내 프린터 상태 확인 (읽기 전용)

v0.9는 같은 네트워크의 Bambu 프린터를 **찾고**, LAN 액세스 코드로 **현재 상태를 한 번
읽어 오는** 화면을 추가합니다. 출력 시작·정지·온도 변경·파일 전송 같은 명령은 보내지
않습니다. 클라우드 계정이나 API 키는 필요 없습니다.

## 사용 순서

1. 왼쪽 메뉴에서 **프린터 상태**를 엽니다.
2. **4초 동안 찾기**로 프린터가 보내는 알림과 검색 응답을 기다립니다. 보이면 **이 프린터 선택**을 누릅니다.
   보이지 않으면 프린터 화면의 IP 주소와 시리얼 번호를 직접 입력합니다.
3. 프린터 화면의 네트워크 설정에서 **LAN 액세스 코드**를 확인해 입력합니다.
4. **현재 상태 읽기**를 누릅니다.

액세스 코드는 그 요청에만 사용합니다. 서버·작업 기록·백업에 저장하지 않고, 응답이나
오류 메시지에 다시 포함하지 않습니다. 화면을 닫으면 입력값도 사라집니다.

## 결과의 단계

각 단계는 서로 다른 사실입니다. 앞 단계가 성공했다고 다음 단계를 성공으로 표시하지 않습니다.

| 연결 상태 | 의미 |
|---|---|
| `unreachable` | 이 주소의 8883 포트에 연결하지 못함 (주소·네트워크·전원 확인) |
| `tls_failed` | 포트는 열렸지만 보안 연결을 시작하지 못함 (Bambu 프린터가 아닐 수 있음) |
| `certificate_changed` | 이 화면에서 앞서 고정한 인증서와 다름 → **액세스 코드를 보내기 전에 중단** |
| `access_rejected` | 프린터가 액세스 코드를 거부함 |
| `subscribe_rejected` | 접속은 됐지만 이 시리얼의 상태 구독이 거부됨 |
| `no_report` | 접속·구독은 됐지만 제한 시간 안에 이 시리얼의 보고가 없음 (시리얼 확인) |
| `protocol_error` | 응답을 해석할 수 없어 중단 |
| `reporting` | 프린터가 자신의 시리얼 주제로 현재 상태를 보고함 |

`reporting`일 때 보여 주는 값은 모두 **프린터가 보고한 값**입니다.

- 출력 상태(대기·준비·출력 중·일시 정지·완료 보고·실패 보고), 진행률, 남은 시간, 레이어
- 노즐·베드 온도와 목표 온도, 노즐 지름·종류
- 오류 코드와 HMS 코드(의미는 프린터 화면이나 제조사 안내에서 확인)
- AMS·외부 스풀에 등록된 재료 정보(사용자가 프린터에서 설정한 값일 수 있음)
- 제품명·펌웨어(버전 요청에 응답한 경우)

보고되지 않은 항목은 “보고되지 않음”으로 남깁니다. 다른 기종의 값으로 채우지 않습니다.
“완료 보고”는 치수·품질을 측정한 결과가 아닙니다. 실물 결과는 **작업 기록**에 직접 남겨 주세요.

## 인증서

프린터는 일반 인증 기관에서 확인할 수 없는 기기 인증서를 사용합니다. 그래서 발급 기관은
확인하지 않고(`issuer_verified: false`), 인증서의 SHA-256을 보여 줍니다. 한 화면에서 처음
`reporting`을 받은 인증서를 그 IP·시리얼에 **고정**하고, 다음 확인부터 다른 인증서가 오면
액세스 코드를 보내기 전에 중단합니다. 프린터를 교체·초기화한 경우에만 **고정한 인증서 해제**를
누르세요. 고정 정보는 페이지를 새로 열면 사라집니다.

## 범위와 제한

- 이 기능은 Bambu 프린터의 LAN 모드에서 관찰되는 SSDP 알림(UDP 2021)과 MQTT over TLS(8883)
  보고 주제를 사용합니다. 제조사가 공개 API로 지원을 약속한 인터페이스가 아니므로 펌웨어에 따라
  동작이 달라질 수 있습니다.
- 보내는 요청은 `pushall`(현재 상태 보고 요청)과 `get_version`(모듈·펌웨어 목록) 두 가지로 고정되어
  있습니다. 다른 요청을 만드는 경로는 없습니다.
- 사설·링크 로컬·루프백 IP 주소만 허용합니다. 호스트 이름과 공인 IP는 네트워크 사용 전에 거부합니다.
- 같은 프린터는 5초 간격으로, 한 번에 한 대만 확인합니다. 일부 기종은 잦은 전체 보고 요청에
  부담을 받을 수 있으니 필요한 때만 확인하세요.
- 찾기는 두 가지를 함께 기다립니다. 프린터가 주기적으로 보내는 알림(UDP 2021)과, 앱이 보낸 검색 요청에
  프린터가 이 PC로 직접 보내는 응답입니다. Bambu Studio가 켜져 있으면 2021 포트를 독점하므로 알림은 받지
  못하지만 검색 응답으로 찾습니다(결과의 `receivers`에 둘 중 무엇을 썼는지 남습니다). 다른 서브넷·게스트
  Wi-Fi·멀티캐스트 차단에서는 결과가 비고, 두 수신 방법이 모두 막히면 `listen_unavailable`이 됩니다.
- 기종 이름은 Bambu Studio 02.09.01.70에 들어 있는 기종 정의의 `model_id`로 만든 표시용 대응표(15개
  기종)입니다. 모르는 코드는 코드 그대로 보여 줍니다. 보고된 연결 방식은 `lan`을 “LAN 전용”,
  `cloud`를 “클라우드”로 함께 표시합니다.

## Klipper 프린터 (Moonraker)

Snapmaker U1, Voron, Sovol, Elegoo Neptune 4, Qidi처럼 Klipper 펌웨어를 쓰는 프린터는 Moonraker 웹 API로
상태를 읽습니다. 프린터 상태 화면 아래쪽 **Klipper 프린터** 카드에 IP, 포트(기본 7125), 필요하면 API 키를 넣고
**현재 상태 읽기**를 누릅니다.

- 보내는 요청은 `GET /server/info`, `/printer/info`, `/printer/objects/list`, `/printer/objects/query` 네 가지로
  고정되어 있습니다. 출력·이동·온도·파일·G-code 요청을 만드는 경로는 없습니다.
- 사설·링크 로컬·루프백 IP만 허용합니다. API 키는 한 번의 확인에만 쓰고 저장하거나 응답에 돌려주지 않습니다.
- 표시: 프린터 보고 상태, 진행률, 레이어, 사용 중인 툴헤드와 툴헤드별 노즐 온도, 베드 온도, Klipper·Moonraker
  버전. 남은 시간은 Moonraker가 직접 보고하지 않으므로 경과 시간과 진행률로 **추정**하고 그렇게 표시합니다.
- Klipper는 필라멘트 종류·색을 보고하지 않으므로 재료 칸, 재고 연결, 출력 전송은 아직 Bambu 전용입니다.
- 결과 상태: `reporting`, `klippy_not_ready`(Moonraker는 응답하지만 Klipper가 준비되지 않음), `access_rejected`
  (401/403, API 키 필요), `not_moonraker`, `unreachable`, `protocol_error`. 상태를 받은 프린터는 2초 뒤에 다시
  확인할 수 있고, 응답을 받지 못한 확인은 간격 제한에 넣지 않아 고친 주소나 키로 바로 다시 시도할 수 있습니다.
- 프린터 없이 확인하려면 합성 서버를 쓰세요(실제 프린터가 아니며 값은 가짜입니다):
  `python scripts/fake_moonraker.py --port 7125 [--api-key 키] [--state printing|standby|paused|complete|error] [--klippy ready|shutdown]`

이 기능은 합성 Moonraker 서버로만 검증했습니다. Snapmaker U1을 포함한 실제 Klipper 프린터에서의 확인은
[검증 기록](VERIFICATION.md)에 장비별로 따로 남기기 전까지 확인된 것으로 보지 않습니다.

## 실제 프린터의 보고 구조 기록하기(필드 점검)

실제 프린터가 보내는 보고의 **구조**를 기록해, 앱이 그 펌웨어의 필드를 제대로 읽는지 확인할 때 씁니다.
프린터와 같은 네트워크의 PC에서 직접 실행하세요. 액세스 코드는 보이지 않는 입력란에 직접 입력하며
어디에도 저장되지 않습니다.

```bash
python scripts/printer_field_probe.py --host 192.168.0.x --serial 프린터시리얼
```

- 앱과 같은 두 읽기 요청(`pushall`, `get_version`)만 보냅니다. 출력 시작·이동·가열·파일 전송은 하지 않습니다.
- 결과는 `qa-output/printer-probe/probe-날짜.json`에 저장됩니다. 원시 보고의 모든 키와 값의 종류, 목록 길이를
  남기고, 상태·온도·노즐·필라멘트 종류와 색·모듈 이름과 버전처럼 식별 정보가 아닌 허용 목록의 값만 그대로 둡니다.
- 시리얼, IP 주소, 액세스 코드, 네트워크·카메라·저장소 정보, 파일과 작업 이름은 기록하지 않습니다. 저장 직전에
  시리얼이나 IP가 남아 있으면 저장하지 않고 멈춥니다.
- 연결이 거부되거나 보고가 없으면 그 결과만 기록하고 종료 코드 1로 끝납니다.

## 프린터 없이 화면 흐름 확인하기

개발·데모용 **합성** 프린터를 이 PC에서 실행할 수 있습니다. 실제 프린터가 아니며 보고 값은 모두 가짜입니다.

```bash
python scripts/fake_bambu_printer.py --access-code abcd1234 --announce --hms
```

앱의 프린터 상태 화면에서 찾기를 누르거나 `127.0.0.1`, 시리얼 `01S00SYNTH000001`, 코드 `abcd1234`를
입력합니다. `--cert other`로 인증서 변경, `--state FAILED`로 실패 보고, `--silent`로 보고 없음 상태를
재현할 수 있습니다. 같은 PC의 8883 포트를 사용하므로 브라우저 자동 테스트 전에는 종료하세요.

## 검증 범위

자동 테스트는 테스트 전용 자체 서명 인증서를 쓰는 루프백 가짜 브로커로 연결 단계, 인증서 고정,
액세스 코드 거부, 보고 누락, 크기 제한과 요청 종류를 확인합니다. 실제 Bambu 프린터와의 연결,
특정 펌웨어의 필드 구성, 네트워크 환경별 찾기 결과는 [검증 기록](VERIFICATION.md)에 장비별로
따로 기록하기 전까지 확인된 것으로 보지 않습니다.
