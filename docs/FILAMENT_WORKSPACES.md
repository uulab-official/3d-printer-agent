# 필라멘트 작업 저장과 주요 설정 편집

작성일: 2026-11-13 (Asia/Seoul).

필라멘트 작업은 **처음 가져온 원본, 문서별 편집본, 검토 대상, 프린터·재료 조건**을 함께 보관합니다. 앱을 다시 열어도 입력을 이어서 다룰 수 있습니다. 원본 파일의 내용을 바꾸거나 프린터에 설정을 적용하는 기능은 아닙니다.

## 이어서 작업하는 흐름

1. **재료 설정**에서 대상 JSON과 필요한 부모 JSON을 가져옵니다. JSON을 붙여 넣었다면 파일 모음에 추가하는 동작으로 현재 내용을 비교 원본으로 보관할 수 있습니다.
2. 검토 대상을 선택하고 **내 프린터와 재료**의 조건을 입력합니다. **프로필 검토하기**로 명시된 상속값과 출처를 확인합니다.
3. 주요 설정 편집에서 바꿀 값을 입력해 선택한 문서에 반영합니다. 상속받은 값을 바꾸면 선택한 자식 문서에 해당 필드만 추가합니다. 원본과 부모 파일, `inherits`는 보존합니다.
4. **작업 이름**을 입력하고 **이 PC에 저장**을 누릅니다. 다른 조합으로 실험하려면 **다른 이름으로 저장**을 사용합니다.
5. 새로고침하거나 앱을 다시 실행한 뒤 **저장된 작업**을 선택하고 **작업 열기**를 누르면 원본·편집본·대상·사용 조건이 복원됩니다. 이전 검토 결과는 복원하지 않으므로 다시 검토합니다.
6. 현재 입력으로 검토한 보고서를 내려받으면 처음 제공한 원본과 검토에 사용한 편집본, 변경 필드, 해시, 장비 조건을 비교할 수 있습니다.

JSON 문법을 고치는 중이라도 작업 저장이 가능합니다. `draft_text`는 파싱하지 않고 문자열로 보관하므로 공백과 줄바꿈, 미완성 내용을 그대로 다시 열 수 있습니다. 검토와 주요 설정 편집에는 올바른 JSON이 필요합니다.

## 주요 설정을 바꿀 때

| 항목 | 편집 대상 |
|---|---|
| 노즐 온도 | `nozzle_temperature` |
| 첫 레이어 노즐 온도 | `nozzle_temperature_initial_layer` |
| 유량 비율 | `filament_flow_ratio` |
| 최대 체적 속도 | `filament_max_volumetric_speed` |
| 베드 온도 | 선택한 플레이트에 대응하는 온도 필드 |
| 첫 레이어 베드 온도 | 같은 플레이트 필드의 `_initial_layer` 값 |

입력한 수치를 편집하는 도구이며 제조사 추천값을 생성하지 않습니다. 사용 조건과 제품에 맞는 값은 원문과 측정 근거로 확인해야 합니다.

숫자 하나, 숫자 문자열 하나, 원소 하나인 배열은 기존 표현을 유지합니다. 예를 들어 `205`는 숫자로, `["205"]`는 문자열 배열로 편집됩니다. 상속값에 새 덮어쓰기를 만들 때는 확인된 원래 값의 형태를 따릅니다. 여러 원소가 있는 배열은 압출기와 인덱스를 추정하지 않고 JSON 편집으로 안내합니다.

입력창을 비운 것이 0이나 기본값을 쓰라는 뜻은 아닙니다. 덮어쓰기를 제거하는 동작은 선택한 문서의 해당 필드만 없애며, 다시 검토했을 때 부모값이 있으면 이어받습니다. 베드 온도 0 등 값 자체의 의미는 기존 검토기가 별도로 검사합니다.

선택한 문서의 편집본을 가져온 원본으로 되돌리거나, 잘못 추가한 문서 하나만 모음에서 제거할 수 있습니다. 제거 때문에 부모가 없어졌다면 다음 검토에서 필요한 부모를 표시합니다. 문서의 제거·복원·수정은 이전 결과와 다운로드를 무효화합니다.

## 변경 후 검증 표시

가져온 파일의 `validation`은 사용자가 제공한 검증 주장입니다. 제조사 인증이나 앱이 관측한 실물 출력 결과가 아닙니다.

파일 모음을 검토하면 처음 가져온 원본 체인과 현재 편집한 체인의 **해석된 설정 전체**를 비교합니다. 대상의 직접 편집뿐 아니라 상위 프리셋에서 이어받는 값의 변경도 감지합니다. JSON 키 순서만 바뀌었거나, 사용하지 않는 문서 또는 자식이 이미 덮어쓴 부모값만 바뀐 경우는 적용 설정의 변경으로 처리하지 않습니다.

적용 설정이 달라졌다면 기존의 긍정적인 검증 주장을 현재 값에 그대로 적용하지 않고 `stale`로 표시합니다. 원본 체인을 해석할 수 없어 비교가 불가능한 경우도 기존 검증을 현재 값에 적용하지 않습니다. 보고서에는 원래 주장을 보존하고 변경 또는 비교 불가 이유를 별도로 남깁니다.

`source.authority`는 원본의 출처 주장으로 유지하며, 변경된 적용값은 별도로 표시합니다. 사용자가 값을 수정했다고 그 수치가 제조사의 권고값이 되지는 않습니다. 원본 없이 단일 JSON만 검토하는 기존 API는 과거 값을 알 수 없으므로 변경 추적을 제공하지 않습니다.

## 저장 충돌과 입력 보호

각 저장본에는 증가하는 `revision`이 있습니다. 두 탭에서 같은 작업을 열고 한 탭이 먼저 저장하면, 나중에 저장하는 탭은 HTTP 409와 충돌 안내를 받습니다. 최신 저장본을 덮어쓰지 않으며, 현재 입력은 남습니다. 현재 내용을 복사본으로 저장하거나 최신 작업을 다시 열 수 있습니다.

다른 탭에서 새로 저장한 작업을 찾으려면 **목록 새로고침**을 사용합니다. 현재 편집 내용은 유지하면서 저장 목록만 다시 가져옵니다. **저장본 삭제**는 확인한 뒤 저장된 기록만 삭제하며, 입력창의 내용은 남겨 새 작업으로 다시 저장할 수 있습니다.

저장 요청을 보낸 뒤 추가로 편집한 내용은 저장 완료로 표시하지 않습니다. 작업을 여는 동안 입력이 바뀌거나 다른 작업으로 이동하면 늦게 도착한 응답으로 새 입력을 덮어쓰지 않습니다. 저장하지 않은 내용이 사라질 수 있는 열기·삭제에는 화면에서 확인을 받습니다.

작업 열기는 입력 복원입니다. 과거 보고서나 준비 가능 표시를 현재 결과처럼 되살리지 않습니다. 앱의 해석 규칙이 바뀌었을 수 있으므로 현재 버전에서 다시 검토해야 합니다.

## 데이터 위치와 제한

`--data-dir` 또는 `PPA_DATA_DIR`로 지정한 앱 데이터 디렉터리의 `profile-workspaces.sqlite3`에 저장합니다. 기본 디렉터리는 `./data/`입니다. CAD 작업 기록과 별도로 관리하며, 작업 하나의 메타데이터와 JSON 전체를 같은 SQLite 트랜잭션으로 갱신합니다. 앱을 종료한 뒤 데이터 디렉터리를 보관하면 CAD 기록과 필라멘트 작업을 함께 옮길 수 있습니다.

- 작업 이름: 앞뒤 공백을 제거한 1–120자.
- 문서 수: 0–64개. 파일 모음이 없으면 붙여 넣은 편집창 내용을 저장합니다.
- 가져온 원본 문서 합계: 2 MiB 이하.
- 원본과 편집 문자열을 포함한 작업: 8 MiB 이하. HTTP 요청 전체에도 8 MiB 제한이 적용됩니다.
- JSON 중첩: 최대 64단계. 브라우저에서 정확히 보존할 수 없는 큰 정수와 비유한 수는 허용하지 않습니다.
- 사용 조건: 알려진 8개 필드, 각 512자 이내의 문자열. 검토 시 노즐 지름을 숫자로 변환하며 저장 시에는 입력 문자열을 보존합니다.

원본 보존은 **파싱한 JSON 객체의 보존**입니다. 원래 파일의 바이트열이나 서식은 보존 대상이 아니며, 편집 문자열은 별도로 정확히 보존합니다. 이 파일 모음은 전체 Bambu Studio 설정이나 Studio로 가져올 수 있는 native preset bundle이 아닙니다.

## API 계약

쓰기 요청에는 기존 `X-Session-Token`, 같은 출처, `application/json` 검사를 적용합니다.

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| GET `/api/profile-workspaces` | 없음 | `{workspaces: [...]}`. 내용 없이 이름·시각·revision·문서 수를 반환 |
| POST `/api/profile-workspaces` | `{title, snapshot}` | HTTP 201, 저장한 작업 전체 |
| GET `/api/profile-workspaces/{id}` | 없음 | 저장한 작업 전체 |
| PUT `/api/profile-workspaces/{id}` | `{title, snapshot, expected_revision}` | 다음 revision의 작업 전체 |
| DELETE `/api/profile-workspaces/{id}` | `{expected_revision}` | `{deleted: true, id}` |

작업 전체에는 `id`, `title`, `revision`, `created_at`, `updated_at`, `snapshot`이 들어 있습니다. ID는 서버가 생성한 32자리 소문자 UUID hex이며 파일 경로로 사용하지 않습니다. 잘못된 입력은 422, 없는 작업은 404, 이전 revision을 사용한 수정·삭제는 409입니다. 충돌 시 현재 저장본은 그대로 남습니다.

빈 파일 모음의 저장 형식 예시:

```json
{
  "title": "재료 설정 초안",
  "snapshot": {
    "schema_version": 1,
    "documents": [],
    "target_index": 0,
    "profile_text": "{\n  \"name\": ",
    "setup": {
      "printer_model": "",
      "printer_preset": "",
      "nozzle_diameter": "",
      "plate_type": "",
      "extruder": "",
      "feed_mode": "",
      "material_id": "",
      "material_identity_status": "unknown"
    }
  }
}
```

파일 모음이 있으면 `documents`는 `{filename, profile, draft_text}`의 목록입니다. `profile`은 처음 가져온 객체, `draft_text`는 현재 편집 문자열이며 `profile_text`는 빈 문자열입니다. `target_index`는 검토 대상 문서의 0부터 시작하는 번호입니다. 저장 가능한 필드는 명시된 것에 한정하며 현재 검토 결과는 포함하지 않습니다.

상속 해석·원본 비교·보고서 구조는 [필라멘트 프리셋 안내](FILAMENT_PRESETS.md), 실제 실행한 검사는 [검증 기록](VERIFICATION.md)에서 확인할 수 있습니다.
