# 현재 제작안 수정

v0.7은 화면에 준비한 치수를 기준으로 변경안을 만듭니다. 수납함, 열린 케이블 받침, 원형 인셋 프레임의 지원 치수를 수정할 수 있습니다. API 키 없이 규칙 모드로 사용할 수 있고, 기존 OpenAI-compatible 연결을 설정했다면 LLM 모드를 선택할 수 있습니다.

## 사용 순서

1. **만들거리 찾기**에서 시작안을 고르거나 치수를 직접 준비합니다. 이미 생성한 작업도 기록에서 열 수 있습니다.
2. **현재 제작안 수정**에 바꿀 항목과 수치를 입력합니다. 예: `높이를 5mm 늘려줘`.
3. 수정안을 요청하고 변경 전후 값을 확인합니다. 이 단계에서는 현재 치수, 모델 파일과 출력 메모가 유지됩니다.
4. 변경안을 적용합니다. 기존 생성 결과는 현재 치수와 달라지므로 화면에서 해제됩니다. 원래 파일은 이전 작업 기록에 남습니다.
5. 치수를 확인한 뒤 모델을 생성합니다. 새 작업에는 원래 시작안과 이번에 선택한 수정 기록이 함께 저장됩니다.

가로 150, 세로 90, 높이 30 mm인 세 칸 수납함에서 `높이를 5mm 늘려줘`를 적용하면 높이만 35 mm가 됩니다. 가로·세로·벽·바닥·칸 수는 그대로 유지됩니다. `가로 160mm, 4칸`은 가로와 칸 수만 변경합니다. 칸 수는 사용자에게 보이는 공간 수이며 내부 기록의 `dividers`는 칸막이 수입니다.

## 지원하는 변경

| 대상 | 수정 가능한 값 |
|---|---|
| 공통 | 가로, 세로, 높이, 벽 두께, 바닥 두께 |
| 수납함 | 칸 수 |
| 열린 케이블 받침 | 홈 수, 케이블 지름, 여유 간격 |
| 원형 인셋 프레임 | 인셋 지름, 인셋 깊이, 여유 간격 |

길이는 mm 또는 cm를 사용하고 결과는 mm로 기록합니다. 길이를 지정한 값으로 바꾸거나 특정 양만큼 늘리거나 줄일 수 있습니다. 칸 수와 홈 수는 원하는 개수를 지정합니다.

규칙 모드는 지원하는 구체적인 표현을 해석합니다. `조금 더 크게`, 전체 배율 변경, 템플릿 변경, 뚜껑·힌지·새 구멍 추가, 서로 다른 두 값을 같은 항목에 지정하는 요청은 다시 입력하도록 안내합니다. 여러 요청 중 일부만 알아듣고 적용하지 않습니다. 치수가 허용 범위 안에 있어도 벽과 내부 공간, 바닥과 높이 등이 충돌하면 변경안을 만들지 않습니다.

LLM도 같은 치수 변경 계약을 사용합니다. 모델이 만든 Python·셸 명령을 실행하지 않습니다. 제공자 연결은 합성 응답으로 계약을 검사하며, 특정 실제 LLM 서비스의 연결·응답 품질을 보장하는 범위는 별도입니다.

## 검토 중에 현재 작업이 바뀌면

수정안을 만든 뒤 치수나 템플릿, 시작안, 연결된 저장 위치가 달라지면 해당 안을 그대로 적용할 수 없습니다. 현재 입력으로 다시 요청하세요. 적용한 뒤 치수를 직접 바꾸면 그 새 수치는 이전 수정안의 승인값으로 기록하지 않습니다.

취소하면 입력한 정확한 치수 문자열과 현재 생성 결과가 유지됩니다. 수정안 요청 실패도 현재 작업을 바꾸지 않습니다. 서버 연결이 끊어졌다면 다시 연결한 뒤 현재 작업 상태를 확인하세요. 생성이나 저장 요청을 자동 반복하지 않습니다.

## 작성 중인 출력 메모

새 제작안을 적용하거나 다시 생성할 때 이전 작업의 저장하지 않은 출력 메모를 원래 작업 ID·저장 위치와 함께 화면에 보관합니다. 새 모델의 결과로 자동 저장하지 않습니다. **저장하지 않은 이전 출력 메모**에서 내용을 복사해 원래 작업에 옮길 수 있습니다.

이 보관은 현재 브라우저 화면의 임시 상태입니다. 브라우저를 닫기 전에 원래 작업에 저장하거나 별도로 복사하세요. 이미 저장한 출력 결과는 기존 작업 기록에 남고, 실제 출력 여부는 계속 사용자 기록으로 구분됩니다.

새 물건을 만드는 일반 요청도 작성 중인 제작안을 바로 덮어쓰지 않습니다. 교체 확인에서 유지하거나 적용할 수 있으며, 확인하는 동안 입력이 다시 달라졌다면 현재 내용을 다시 확인합니다.

## 생성 기록과 파일

새 작업의 `model_edit`에는 요청 문장, 기준 치수, 선택한 변경, 변경 전후, 최종 치수와 SHA-256이 기록됩니다. 이미 생성한 모델을 기준으로 수정했다면 그 작업 ID와 원본 3MF·manifest의 해시도 남습니다. 생성 직전에 다시 확인하여 원본이 사라지거나 달라졌으면 새 작업 생성을 거절합니다.

기록의 `provenance: user_confirmed_parameters`는 사용자가 선택한 치수라는 뜻입니다. LLM이 실제 작성했다는 인증이나 실물 출력 검증은 아닙니다. 기록은 가장 최근에 적용한 수정안이며 모든 대화의 전체 이력은 아닙니다. 생성 전에 여러 번 수정했다면 마지막 안만 새 작업에 기록합니다.

작업 JSON과 manifest, 모델별 ZIP, 전체 백업에 같은 기록이 포함됩니다. 재시작과 복원 뒤에도 원래 시작안과 변경값을 확인할 수 있습니다. 복원한 모델에 저장한 Studio 설정을 적용해 새 준비 3MF를 만드는 과정은 기존과 같습니다. 현재 CAD, 설정 준비, 실제 슬라이싱, 실물 출력은 각각 별도 단계입니다.

## API 예시

변경안 요청에는 현재 템플릿에서 편집 가능한 모든 치수를 명시합니다. 일부만 보내면 나머지를 기본값으로 가정하지 않고 거절합니다. 아래 요청은 세 칸 수납함의 높이만 5 mm 늘립니다.

```json
{
  "text": "높이를 5mm 늘려줘",
  "mode": "templates",
  "base_parameters": {
    "template": "tray",
    "width": 150,
    "depth": 90,
    "height": 30,
    "wall": 2,
    "bottom": 2,
    "dividers": 2
  }
}
```

`POST /api/model-edits/plan`에 로컬 세션 토큰과 함께 전송합니다. 기존 생성 작업을 기준으로 한다면 `parent_job_id`도 전달합니다. 준비된 응답은 `status: ready`와 `review`를 반환합니다. `review.parameters`는 전체 결과 치수이고 `review.changes`는 실제로 달라지는 항목입니다. 다시 입력할 필요가 있는 응답에는 적용 가능한 `review`가 없습니다.

사용자가 확인한 뒤 `POST /api/models`에 `review.parameters`의 치수와 `model_edit: review.selection`을 보냅니다. 원래 시작안을 유지한다면 기존 `project_selection`도 함께 전달합니다. 서버는 변경값을 다시 계산하여 제출한 치수와 대조합니다. 다른 치수를 끼워 넣으면 422, 기록된 기준 모델이 바뀌었으면 409 `model_edit_parent_changed`를 반환하고 CAD 작업을 예약하지 않습니다.

기존 `/api/plan`은 새 제작안을 만드는 API로 유지됩니다. 일반 요청의 여러 XYZ 치수가 서로 다르면 첫 번째 값만 골라 쓰지 않고 확인을 요청합니다. `120x80x35mm`와 `12x8x3.5cm`처럼 같은 크기를 다른 단위로 반복한 표현은 같습니다.
