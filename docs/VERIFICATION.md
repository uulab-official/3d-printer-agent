기존 CAD 흐름에 다음 두 시나리오를 데스크톱과 모바일에 각각 추가했습니다.

1. 자식 프리셋만 가져오기 → 누락 부모 이름 확인 → 부모 추가 → 자식의 편집값과 부모의 상속값·출처 확인 → 보고서 다운로드 → 원본·편집본·장비 조건 확인 → 입력 변경 시 결과와 다운로드 해제 → 대상별 편집본 유지와 단일 JSON 검토 복귀.
2. 미지원 include 차단 → 잘못된 JSON 파일 추가 → 기존 편집 내용 유지, 이전 결과와 다운로드 해제.

UI는 HTML처럼 보이는 설명 문자열을 실행하지 않고 텍스트로 표시했습니다. 실제 브라우저에서 내려받은 보고서 2개를 별도로 읽어 원래 값과 편집한 값의 보존, 각 제출 문서의 canonical SHA-256 일치를 다시 확인했습니다. 데스크톱·모바일 상속 검토 스크린샷도 확인했습니다.

독립 코드 검토에서는 500단계 배열을 포함한 작은 JSON이 HTTP 500을 반환하는 문제를 재현했습니다. 전체 JSON 중첩을 64단계로 제한한 뒤 profile과 setup 모두 HTTP 422와 설명을 반환하도록 수정했고, 정상 경계와 전체 회귀 검사를 통과했습니다.

[browser-evidence 산출물](https://github.com/uulab-official/3d-printer-agent/actions/runs/43351259244/artifacts/14003094848)은 7일간 보관됩니다. 테스트 설정값은 합성 fixture이며 필라멘트 추천값이 아닙니다. 이 실행은 Bambu Studio와 LLM이 미설정인 조건을 사용했으며 실제 프린터·실물 휴대폰·실제 모델 서버를 검증하지 않았습니다. 지원 범위는 [필라멘트 프리셋 안내](FILAMENT_PRESETS.md)에 기록했습니다.

## 패키지와 실제 HTTP 경로

인터넷에서 의존성을 새로 설치하지 않고 `pip install --no-index --no-deps --no-build-isolation --target ... .`로 패키지를 빌드·설치했습니다. 소스 폴더 밖에서 설치한 모듈로 서버를 시작하고 실제 HTTP 요청으로 아래 경로를 확인했습니다.

- bootstrap과 HTML·CSS·JavaScript 배포 및 응답 정책 헤더
- “14cm × 9cm × 4cm 수납함 3칸” → 실제 CAD 생성 → 파일 SHA-256 일치 → ZIP 다운로드
- 입력이 부족한 프로필의 `needs_input`, 배송비가 미확인인 상품의 단가 미확정
- 작업 이력과 사용자 보고 결과 저장

모든 HTTP 검사가 통과했습니다. 상세 기록은 [HTTP_EVIDENCE.json](HTTP_EVIDENCE.json)에 있습니다. 이는 브라우저 렌더링이나 다른 PC의 의존성 설치를 검증한 결과가 아닙니다.

## 코드 검토에서 수정한 문제

- 대상 물건 이름이 있는 필라멘트·구매 질문을 제작 요청으로 오해하는 분기를 수정했습니다.
- 새 슬라이싱이 실패했는데 이전 파일이 현재 결과처럼 남는 다운로드 별칭을 해제합니다.
- 원형 수납함·손잡이 등 알려진 미지원 형상을 기본 모델로 축약하지 않도록 확인 경로를 추가했습니다. 템플릿에 적용되지 않는 비기본 파라미터는 거절합니다.
- 개별 치수의 단위, 인셋 깊이, `.8` 표기, 서로 충돌하는 칸 수를 확인합니다.
- LLM의 자유 텍스트가 출력 완료 같은 실행 사실을 선언하지 않도록 사용자 상태 문장은 앱이 생성합니다.

규칙 파서는 제한된 문법입니다. 모든 자연어 제약의 인식을 검증했다는 뜻은 아니며, 생성 전 치수 편집과 기본값 표시를 유지합니다.

## 화면 검증의 제한

한국어 UI, 반응형 CSS, Canvas 3D 미리보기, 생성·다운로드·설정·가격·이력 연결 코드를 구현했습니다. JavaScript 문법과 HTML ID/label/DOM 참조, inline script/style/event-handler 부재를 확인했습니다.

`node tests/test_ui_state.cjs` → **4개 상태 회귀 검사 통과**. 제작안 변경 시 이전 결과 해제, 실행 없는 저장 계획 표시, 슬라이싱 준비 후 다운로드 갱신, 작업 진행 중 다른 모델 생성 잠금을 실제 컨트롤러 함수와 DOM 대역으로 검사했습니다. 이 수치는 위 Python 테스트 88개와 별도로 집계합니다.

앱의 실제 `MeshViewer` 클래스와 세 샘플의 STEP 메시를 별도의 Canvas 래스터라이저에서 실행해 이미지도 확인했습니다. 삼각형의 평균 깊이로 그리던 방식에서 내부 면이 잘못 겹치는 문제를 발견했고, 픽셀별 깊이 버퍼로 수정했습니다. [모델 미리보기 이미지](../examples/model-preview.png)는 이 검사에서 나온 실제 형상입니다. 브라우저의 CSS·이벤트·모바일 성능 검증과는 구분합니다.

초기 로컬 환경의 실제 브라우저 검사는 **완료하지 못했습니다**. Playwright 기본 브라우저가 설치되지 않았고, 사용 가능한 Chromium 실행은 환경의 IPC 소켓 정책으로 차단되었습니다. 권한 확장 요청은 설정된 자동 승인 정책에서 거절되었습니다. 정책을 바꾸거나 우회하지 않았습니다. 이후 공개 저장소의 GitHub Actions에서 실행한 브라우저 검증은 문서 상단에 별도로 기록했습니다.

초기 로컬 검사만으로는 모바일 레이아웃, 실제 픽셀 렌더링, 마우스·터치·키보드 상호작용을 확인할 수 없었습니다. 위 CI에서 확인한 경로 외에, 사용자 PC와 실제 입력 장치에서 추가로 확인할 항목은 다음과 같습니다.

1. 첫 화면의 세 템플릿과 서버 상태 표시.
2. 자연어 제작안에서 치수·기본값을 확인한 뒤 모델 생성.
3. 실제 메시 회전·확대, STL·STEP·3MF·전체 ZIP 다운로드.
4. 빈 필라멘트 JSON이 정보 입력 필요로 표시되는지 확인.
5. 배송비 미확인과 무료 배송을 구분하는 가격 비교.
6. 작업 기록 재열기와 사용자 결과 저장, 작은 화면에서 메뉴·폼 사용.

## 아직 검증하지 않은 범위

Windows/macOS 설치, 다른 Python·CadQuery 버전, 실제 Bambu CLI·프리셋 상속 해석·장비 연결·출력 시작, 실제 LLM 이해 성능, 외부 모델 검색·리믹스, 제조사 출처 인증, 실시간 상품 가격, 실물 맞춤·강도·재료 적합성은 후속 검증입니다.

[BENCHMARKS.md](BENCHMARKS.md)의 30개 사례는 후속 평가 계획이며 위 88개 테스트의 성적과 혼합하지 않습니다.
