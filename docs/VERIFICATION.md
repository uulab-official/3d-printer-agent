### 구매 입력과 실제 브라우저

새 흐름은 실제 비교 API의 응답을 지연하고 처리 중인 입력·외부 통화 선택이 잠긴
상태와 일치하는 결과를 확인합니다. 완료 후 입력을 바꾸면 이전 결과를 해제하고,
명시적인 합성 HTTP 503 뒤에는 사용자가 다시 비교해야 복구됩니다. 배송비 미입력과
0원을 구분하는 기존 계산도 유지합니다. 처음 조사한 프로그램 방식의 DOM 편집은
실제 잠긴 폼의 사용자 조작과 구분하며, 일반 사용자가 처리 중인 폼을 수정할 수
있었다고 주장하지 않습니다.

종료 보호 검사는 취소 가능한 `beforeunload` 이벤트의 처리 여부를 확인합니다.
브라우저의 실제 종료 확인 창이나 자동 초안 저장을 검증한 것은 아닙니다.
백업 안내는 저장 위치 영역 안에 접힌 도움말로 제공하며, 전체 작업 백업과 모델별
ZIP, 저장하지 않은 브라우저 입력의 차이를 설명합니다.

최종 브라우저 산출물의 독립 확인 **97개**에서 정확한 커밋·34개 시나리오의
첫 실행 성공, 비교 요청·응답, 배송비와 단가 계산을 다시 대조했습니다. 구매 편집·
재시도와 저장 위치·복구 영역의 구성 요소 캡처를 데스크톱·모바일 각 세 장씩
확인했습니다. 모바일 구매 캡처에서는 포커스된 본문 건너뛰기 링크와 고정 헤더가
카드 상단 일부에 겹치며, 가로 스크롤 표의 오른쪽 배송비·단가 열은 현재 캡처
밖에 있습니다. 주요 비교 버튼·통화·가격 입력은 보이지만 모든 영역이 가림 없이
담겼다고 주장하지 않습니다. 저장 경로와 접힌 백업 도움말 제목은 두 화면에서
확인했습니다. 펼친 도움말·링크 클릭·전체 페이지·실물 휴대폰 검증은 포함하지 않습니다.

### 실제 실패와 독립 검토에서 수정한 항목

최초 기능 커밋 `e15030fb7526ac2e75542be9d94579a1c2007291`의
[설치 실행 43594078275](https://github.com/uulab-official/3d-printer-agent/actions/runs/43594078275)는
Linux·macOS에서 성공하고 Windows 백업 생성에서 실패했습니다. Windows의 캐시된
디렉터리 정보, 경로와 열린 파일의 생성 시각·실행 권한 표현 차이가 정상 파일을
변경된 것으로 판단하는 원인이었습니다. `7c70cb6f0ce0d746150e486a2ed9196604950002`에서
같은 의미의 파일 식별 정보를 비교하도록 수정했고, 이후 세 OS에서 각각 133개를
통과했습니다. 읽는 도중의 실제 변경을 거절하는 별도 검사도 유지합니다.

그 커밋의 세 workflow는 성공했지만
[첫 실제 승격 43595184660](https://github.com/uulab-official/3d-printer-agent/actions/runs/43595184660)은
Actions 산출물 다운로드의 HTTP 415로 릴리스 쓰기 전에 중단됐습니다.
Actions의 리다이렉트 요청에는 GitHub JSON, 릴리스 파일 요청에는 binary media type을
명시하도록 수정했습니다. 해당 헤더 차이를 재현하는 회귀 검사와 독립 재검토를
통과한 최종 커밋에서 세 workflow를 다시 실행한 결과가 위 표입니다. 릴리스 관련
파일 변경도 native 검증을 시작하도록 경로 조건을 추가했으며 native job 내용은
그대로 유지했습니다.

독립 코드 검토에서는 WAL 검사 중 원본 보조 파일 변경, 순서·자료형이 다른 SQLite
열 구조 허용, 지원하지 않는 ZIP 버전의 CLI 예외 노출을 재현하고 수정했습니다.
WAL은 임시 복사본에서 커밋된 내용까지 읽고 원본을 보존하며, 시작 전에 지원되는
열 구조를 순서까지 확인합니다. 릴리스 검토에서 발견한 재실행 산출물 이름 충돌과
업로드 중 workflow 실행 차수 변경도 수정하고 실패 반례를 다시 통과시켰습니다.

### Native 회귀와 공개 자산의 확인 범위

실제 Linux Studio에서 원본 STL 큐브와 CadQuery 케이블 정리 3MF가 각각 어댑터
32개·독립 설정 비교 30개·qualification 9개를 통과했습니다. 내려받은 새 native
산출물의 독립 확인 **95개**에서도 소스·공식 입력·출력 ZIP·G-code·설정·해시가
일치했습니다. native 실행 설정과 기존 어댑터는 그대로이며, 같은 소스의 릴리스
검증을 보장하기 위한 workflow 경로 조건만 추가됐습니다.

릴리스 445286167에는 wheel, `SHA256SUMS`, `wheel-receipt.json`,
`release-evidence.json`, 운영체제별 `qualification-*.json` 세 개가 있습니다.
승격 작업은 올린 파일 7개를 각각 다시 내려받아 바이트를 확인한 뒤 공개했습니다.
tag 생성 직전과 공개 직전에 위 세 workflow ID·첫 실행·성공 상태가 유지됨을
다시 확인했습니다. 일부 검사가 끝나기 전의 앞선 완료 이벤트는 실제로 `skipped`를
기록하고 게시하지 않았습니다.

공개 후 별도 검토에서 자산 일곱 개를 인증 없이 다시 내려받고 **31개 독립 확인**을
통과했습니다. 모든 실제 파일의 크기·SHA-256이 공개 API와 승격 보고서에 일치합니다.
wheel·영수증·체크섬·세 플랫폼 보고서는 검사한 패키지 산출물의 원본 바이트와 같고,
릴리스 근거 JSON도 최종 소스·실행·산출물·플랫폼 보고서에서 재구성한 내용과
일치합니다. 같은 tag의 공개 릴리스는 하나이며 중복 자산은 없습니다.

상세 Actions 산출물의 보관 기간은 패키지·승격 보고서 14일, 브라우저·native 7일입니다.
공개 릴리스의 wheel과 보고서 일곱 개는 해당 단기 보관 기간과 별도로 유지됩니다.

이 공개 wheel은 서명된 DMG/MSI나 자동 업데이트 프로그램이 아닙니다. 검증은 로컬

수집, 공개 다중 사용자 서비스와 실물 프린터 출력은 별도 구현·검증 범위입니다.

### 실제 브라우저의 중단·복구·이력

새 흐름은 실제 Python 서버를 재시작해 만료된 세션의 HTTP 403을 확인하고,
명시적인 재연결 후 숫자 입력 `-`, 요청 문장, 미완성 필라멘트 JSON을 보존합니다.
서버에서 실제 CAD 생성이 끝난 성공 응답을 지연시킨 상태에서 먼저 재연결하고,
늦은 응답이 현재 화면을 바꾸지 않으며 작업 기록에서 별도로 열 수 있음을 확인합니다.
CAD 생성은 대역으로 바꾸지 않았고, 재연결 중 변경 요청을 자동 재전송하지 않습니다.

다른 흐름은 실제 CAD 하나에 합성 실패 102개·중단 하나·읽을 수 없는 기록 하나를
추가한 뒤 서버를 재시작합니다. 유효 기록 104개, 중단 처리 1개, 읽기 확인 1개가
표시되고 페이지를 이어 읽어 총 105개 중 가장 오래된 실제 CAD를 엽니다.
목록 실패 복구 검사에는 지연한 실제 응답과 명시적인 합성 HTTP 503을 사용합니다.
오래된 실패가 새 목록을 덮지 않으며, 현재 새로고침 실패도 기존 목록을 지우지 않습니다.

새 브라우저 산출물의 독립 검사 **54개**에서 복구된 모델의 실제 3MF 해시와
90 × 60 × 18 mm 치수, 원본 출처, 부분 결과 부재, 이력 복구 기록을 확인했습니다.
브라우저가 저장한 job/manifest JSON 스냅샷은 재직렬화되어 `90.0`을 `90`으로
표현하므로 원본 바이트라고 취급하지 않았습니다. 스냅샷의 값은 원래 작업 파일과
비교하고, 설계 해시는 원래 JSON으로 재계산했으며 manifest 원본은 별도 저장된
바이트 영수증과 대조했습니다. 이 구분 없이 스냅샷에서 해시를 다시 계산하던 초기
검사기의 실패는 해당 검사기만 바로잡았습니다. 제품 코드를 변경한 실패는 아닙니다.
기존 추천·출처·다운로드 흐름에도 새 산출물로 **57개**의 독립 회귀 검사를 적용했습니다.

데스크톱·모바일에서 각각 연결 만료, 재연결, 시작 복구, 모델 교체 확인, 오래된
CAD 카드의 스크린샷을 확인했습니다. 총 10개 구성 요소 이미지에서 주요 버튼과
경로·설명 문구가 잘리지 않았습니다. 긴 저장 경로는 작은 화면에서 줄바꿈됩니다.
전체 페이지 시각 검사, 색상 대비 측정, 실물 휴대폰 검증으로 확대하지 않습니다.

### 실제 실행으로 발견한 추가 계약

첫 앱 어댑터 실행 [43375168823](https://github.com/uulab-official/3d-printer-agent/actions/runs/43375168823), 커밋 `d0a67c16d8366ab2fdda14e920893fbaffa64fd6`은 STL·3MF 모두 native 종료 코드 239, 내부 코드 -17로 실패했습니다. 어댑터는 두 결과를 `failed`로 반환하고 출력 파일·해시를 성공 결과로 승격하지 않았습니다. 원인은 합성 machine의 `from: "user"`에 시스템 부모가 없고 process에 명시적 호환 목록이 없었던 것입니다.

고정한 upstream 소스에서 이 동작을 확인했습니다. CLI는 `from: "system"`인 machine에는 `name`을 시스템 이름으로 사용하고, user machine에는 `inherits`를 사용합니다. 새 process의 `compatible_printers`가 해당 이름과 정확히 일치해야 합니다. 이에 따라 현재 지원하는 해소된 루트 구성의 계약을 명시하고, 사용자 machine 계보·누락 또는 불일치한 process 호환 목록을 준비 단계에서 설명과 함께 차단합니다. 사용자 파일의 `from`이나 상속·호환 목록을 자동으로 바꾸지는 않습니다.

별도의 합성 CI fixture에는 명시적인 native 루트 분류와 그 이름을 참조하는 process 호환 목록을 사용합니다. 이 분류는 제조사 출처를 뜻하지 않으며, 실제 provenance는 합성 입력으로 기록합니다. native 기본값에 의존하는 최소 설정이라 실제 장비용 추천 프리셋으로 배포하지 않습니다.

독립 코드 검토에서는 출력 설정의 1,200단계 배열이 재귀 비교에서 오류를 일으키고, 64단계의 비정상 래핑이 정상값으로 비교되는 문제를 재현했습니다. 디코딩한 설정의 컨테이너 깊이를 32로 제한하고 JSON 파서의 재귀 오류도 처리했습니다. 손상된 입력 프로젝트 설정은 준비 전에 차단하며, 손상된 출력 설정은 `needs_review`로 반환합니다. 선택 플레이트의 온도 0이 native에서 미지원 조합을 뜻하는 규칙도 확인해 준비 단계에서 거절하고, 미선택 플레이트의 0은 보존합니다.

1. 긍정적인 검증 주장이 있는 자식·부모 JSON 가져오기 → 사용 조건 입력 → 상속값 검토 → 유량 비율을 자식의 덮어쓰기로 편집 → 원본·편집본·대상·조건 저장 → 새로고침 후 다시 열기 → 이전 결과가 없음을 확인 → 새 검토에서 기존 검증의 재확인 필요 표시 → 보고서 다운로드.
2. 같은 작업에 문법이 완성되지 않은 JSON 문자열 저장 → 새로고침 후 정확한 문자열 복원 → 원본 복원 → 부모 파일 하나 제거 → 누락된 부모 안내 확인.
3. 다른 탭의 저장을 실제 API로 재현 → 오래된 revision의 저장은 409 → 현재 편집 유지 → 별도 복사본 저장 → 복사본의 저장본만 삭제하고 현재 입력과 다른 탭의 저장본은 유지.

각 흐름을 데스크톱과 모바일 화면에서 실행했습니다. 첫 두 흐름은 하나의 연속 테스트에 들어 있으므로 프로젝트당 새 테스트는 2개입니다. API나 CAD 결과를 가짜 응답으로 대체하지 않았습니다.

브라우저가 내려받은 workspace 보고서 2개를 다시 읽었습니다. 부모 원본과 현재 문서가 같고, 원래 자식에는 없던 유량 필드만 편집본에 추가되며, `inherits`와 원래 검증 메타데이터가 보존됨을 확인했습니다. `validation_status`는 `stale`, `can_prepare_profile`은 `false`였고 변경 필드는 정확히 하나였습니다. 원본과 편집본의 모든 canonical SHA-256을 별도로 계산해 보고서와 대조했습니다. 장비 조건 8개도 보존됐습니다.

독립 코드 검토에서 다음 두 문제를 재현하고 수정했습니다.

- 저장본을 여는 중에 선택한 파일이 늦게 읽히면 앞선 열기 응답이 그 파일을 버리는 경쟁 상태. 파일 선택을 시작한 시점부터 새 편집으로 기록해 앞선 열기가 덮어쓰지 못하도록 했습니다.
- 큰 원본의 편집본을 줄인 뒤 다른 파일을 추가하면 원본 합계가 2 MiB를 넘어도 가져오기가 성공하는 문제. 편집본과 보관할 원본의 한도를 각각 검사하고, 실패 시 기존 원본과 초안을 유지합니다. 붙여 넣은 JSON을 원본으로 채택할 때도 같은 제한을 적용합니다.
