### 기존 치수와 시작안을 유지하는 수정 흐름

기존 23개 시나리오에 두 시나리오를 더해 두 화면 크기에서 실행했습니다.
첫 흐름은 세 칸 책상 정리함 시작안 선택 → 실제 CAD 생성 → 출력 메모 작성 →
“높이를 5mm 늘려줘” 검토 → 취소해 기존 값 유지 → 다시 검토하고 키보드로 적용 →
새 CAD 생성·다운로드 → 수동 편집으로 선택 해제 → 이력에서 기록 다시 열기입니다.
기존 **150 × 90 × 30 mm**에서 **150 × 90 × 35 mm**로 높이만 바뀝니다.
나머지 치수와 원본 시작안의 식별 정보는 유지합니다.

다운로드한 부모·자식 3MF와 원래 manifest의 실제 바이트에서 모델·manifest 해시,
전체 치수·변경값·검토 기록의 해시와 시작안 참조를 다시 계산했습니다.
기준 모델이 연결된 수정안에는 생성 직전 다시 확인할 원래 작업과 파일 해시가 들어갑니다.
자식 모델의 기록과 manifest가 검토한 변경안에 일치하고 실제 메시도 수정한 치수와 같습니다.
새 작업의 출력 결과와 메모는 비어 있으며, 이전 메모는 원래 작업의 식별 정보와 함께 남습니다.
이력에서 다시 열어도 과거 기록을 새로 적용할 수정안으로 취급하지 않습니다.

두 번째 흐름은 기존 CAD와 미저장 메모를 둔 상태에서 **140 × 85 × 32 mm** 새 제작안을
요청하고, 완료된 뒤 교체 확인을 취소·적용하는 과정입니다. 같은 치수로 다시 생성할 때에도
각 메모는 원래 작업에 연결해 보관합니다. 정확한 공백과 줄바꿈을 포함한 메모 보존,
취소·키보드 적용·수동 변경·이력 열기의 클릭 시점은 통과한 CI assertion으로 확인합니다.
저장된 JSON·메시와 스크린샷만으로 전체 입력 시점을 독립 재실행했다고 주장하지 않습니다.

서로 다른 원래 작업에 연결된 미저장 메모 두 개가 보입니다. 모바일에서는 메모와 긴 저장

### 브라우저에서 발견해 수정한 수치 정규화 문제

첫 구현 [`f91aab4`](https://github.com/uulab-official/3d-printer-agent/commit/f91aab459a80e7bc22129d977d8c425fa651c5db)의
[CI 43694011874](https://github.com/uulab-official/3d-printer-agent/actions/runs/43694011874)은
기존 흐름 등을 포함한 48개가 통과했지만 새 수정 흐름 두 개에서 실패했습니다.
Python의 길이 변경값 `5.0`이 브라우저 JSON을 거쳐 `5`가 되면서 검토 해시가 바뀌었습니다.
이전 설치·native 성공을 조합해 릴리스하지 않았습니다.

모든 길이 값은 해시 계산 전에 같은 부동소수 표현으로, 음수 0은 양수 0으로 정규화합니다.
개수는 엄격한 정수로 유지하며 원래 숫자·형상 검사와 저장 기록의 정확한 재계산 검증을
완화하지 않습니다. 실제 Node JSON 직렬화와 음수 0 부모를 포함한 CAD API 회귀를 추가해
실패를 재현한 뒤 수정했습니다. 이후 브라우저에서는 수치·기록 일치와 다운로드 형상 검사가 통과했습니다.
개발용 전체 Python 테스트는 Node.js 22 이상이 필요하며 앱 실행에는 Node가 필요하지 않습니다.

### 이력 목록의 수정 기록 전달 보완

두 번째 소스 [`0975fa4`](https://github.com/uulab-official/3d-printer-agent/commit/0975fa4520b6511ec0fdbf7b6237b144999e8f9e)의
[CI 43694957950](https://github.com/uulab-official/3d-printer-agent/actions/runs/43694957950)에서도
48개가 통과하고 두 수정 흐름은 이후 이력 표시 단계에서 실패했습니다. 원래 작업·manifest에는
수정 기록이 있지만 SQLite의 목록 요약에는 없어 화면에 전달되지 않았습니다.
실제 trace의 목록 응답과 저장된 화면 상태에서 같은 누락을 확인했습니다.

목록은 현재 페이지에 표시할 작업만 같은 저장소 잠금 아래에서 읽고, 검증한 수정 기록만
덧붙입니다. 기존 여섯 요약 필드·정렬·커서는 유지하며, 손상·누락된 작업은 고정된 읽기 오류로
표시합니다. DB 변경·전체 이력 스캔·부모 재귀 조회·모델 파일 재읽기는 하지 않습니다.
페이지마다 추가 파일 읽기가 생기며 대규모 이력의 지연 시간을 인증한 것은 아닙니다.

실제 저장/API 회귀 5개로 실패를 재현해 수정하고, 설치 검사에는 생성 직후·재시작 후·복원 후
정확히 하나의 자식 기록과 전체 수정 기록이 일치하는 세 검사를 추가했습니다.
운영체제마다 생성 직후 4개·재시작 후 5개·복원 후 5개 목록 항목을 보관하며, 세 운영체제의
응답 본문 9개에서 기존 여섯 요약 필드와 선택적 수정 기록·정렬·기존 작업의 기록 생략을 대조했습니다.
이 세 검사 없이 게시하지 않는 조건도 회귀로 검증했습니다. 실제 목록 응답을 JSON으로
다시 직렬화해 보관하며, 그 구조·값을 독립 대조한 결과와 원래 HTTP wire 바이트를 구분합니다.
독립 검토를 거친 최종 `62317af`에서 세 workflow를 모두 다시 통과시켰습니다.

### 실제 native 회귀와 남은 진단

기존 네 합성 경로의 새 산출물 재검사는 **251개(독립 데이터 238개 + CI 기록 일관성 13개)**를
통과했습니다. 커밋된 입력·스크립트와 출력의 전체 설정·메시·파일 해시를 대조했습니다.
현재 케이블 CAD는 정점 1,384개·삼각형 1,332개, **80 × 18 × 12 mm**이며,
여섯 합성 설정 변경 외 원본 606개 값은 준비 단계에서 그대로입니다.
프로젝트의 native 출력은 유효 설정 610개가 같고, wipe-tower 좌표 두 개의 정규화와 빈
`upward_compatible_machine` 추가만 다릅니다. 실제 G-code motion 명령 수는 큐브 STL
**629개**, 케이블 3MF **14,988개**, 원본 프로젝트와 편집 프로젝트 각각 **14,923개**입니다.

일곱 stderr 파일은 비어 있지만 stdout에는 `FillFloatingConcentric` ZFiller 오류
**4개**(원본·편집 프로젝트 각각 인덱스 11·45), Wayland 연결 실패 **9개**, glfwInit 실패
**9개**, bootstrap의 invalid `T65535` 명령 **1개**가 남습니다. 14개 로그 본문을 읽고
JSON에 중복된 stdout 사본은 다시 세지 않았습니다.
기록된 종료 코드 0과 파일·설정·형상 검사의 성공은 실제 도구 경로 품질을 입증하지 않습니다.
이번 로그의 진단 위치와 motion 수를 새로 읽었으며 이전 실행의 수치를 복사하지 않았습니다.

`first_layer_time`은 큐브에서 `325083569299397202906704379258077184.000000`,
케이블 3MF에서 `4730596.000000`, 두 프로젝트에서 `0.000000`으로 기록됐습니다.
이 값의 물리적 정확성은 검증하지 않았습니다. G-code의 필라멘트 체적 단위 표기도 검증하지 않았습니다. 이를 출력 시간·재료

### 공개 전 발견해 수정한 문제

### 구매 입력과 실제 브라우저

### 실제 브라우저의 중단·복구·이력

새 흐름은 실제 Python 서버를 재시작해 만료된 세션의 HTTP 403을 확인하고,
명시적인 재연결 후 숫자 입력 `-`, 요청 문장, 미완성 필라멘트 JSON을 보존합니다.
서버에서 실제 CAD 생성이 끝난 성공 응답을 지연시킨 상태에서 먼저 재연결하고,
늦은 응답이 현재 화면을 바꾸지 않으며 작업 기록에서 별도로 열 수 있음을 확인합니다.
CAD 생성은 대역으로 바꾸지 않았고, 재연결 중 변경 요청을 자동 재전송하지 않습니다.

다른 흐름은 실제 CAD 하나에 합성 실패 102개·중단 하나·읽을 수 없는 기록 하나를
추가한 뒤 서버를 재시작합니다. 유효 기록 104개, 중단 처리 1개, 읽기 확인 1개가
표시되고 페이지를 이어 읽어 총 105개 중 가장 오래된 실제 CAD를 엽니다.
목록 실패 복구 검사에는 지연한 실제 응답과 명시적인 합성 HTTP 503을 사용합니다.
오래된 실패가 새 목록을 덮지 않으며, 현재 새로고침 실패도 기존 목록을 지우지 않습니다.

새 브라우저 산출물의 독립 검사 **54개**에서 복구된 모델의 실제 3MF 해시와
90 × 60 × 18 mm 치수, 원본 출처, 부분 결과 부재, 이력 복구 기록을 확인했습니다.
브라우저가 저장한 job/manifest JSON 스냅샷은 재직렬화되어 `90.0`을 `90`으로
표현하므로 원본 바이트라고 취급하지 않았습니다. 스냅샷의 값은 원래 작업 파일과
비교하고, 설계 해시는 원래 JSON으로 재계산했으며 manifest 원본은 별도 저장된
바이트 영수증과 대조했습니다. 이 구분 없이 스냅샷에서 해시를 다시 계산하던 초기
검사기의 실패는 해당 검사기만 바로잡았습니다. 제품 코드를 변경한 실패는 아닙니다.
기존 추천·출처·다운로드 흐름에도 새 산출물로 **57개**의 독립 회귀 검사를 적용했습니다.

데스크톱·모바일에서 각각 연결 만료, 재연결, 시작 복구, 모델 교체 확인, 오래된
CAD 카드의 스크린샷을 확인했습니다. 총 10개 구성 요소 이미지에서 주요 버튼과
경로·설명 문구가 잘리지 않았습니다. 긴 저장 경로는 작은 화면에서 줄바꿈됩니다.
전체 페이지 시각 검사, 색상 대비 측정, 실물 휴대폰 검증으로 확대하지 않습니다.

### 실제 실행으로 발견한 추가 계약

첫 앱 어댑터 실행 [43375168823](https://github.com/uulab-official/3d-printer-agent/actions/runs/43375168823), 커밋 `d0a67c16d8366ab2fdda14e920893fbaffa64fd6`은 STL·3MF 모두 native 종료 코드 239, 내부 코드 -17로 실패했습니다. 어댑터는 두 결과를 `failed`로 반환하고 출력 파일·해시를 성공 결과로 승격하지 않았습니다. 원인은 합성 machine의 `from: "user"`에 시스템 부모가 없고 process에 명시적 호환 목록이 없었던 것입니다.

고정한 upstream 소스에서 이 동작을 확인했습니다. CLI는 `from: "system"`인 machine에는 `name`을 시스템 이름으로 사용하고, user machine에는 `inherits`를 사용합니다. 새 process의 `compatible_printers`가 해당 이름과 정확히 일치해야 합니다. 이에 따라 현재 지원하는 해소된 루트 구성의 계약을 명시하고, 사용자 machine 계보·누락 또는 불일치한 process 호환 목록을 준비 단계에서 설명과 함께 차단합니다. 사용자 파일의 `from`이나 상속·호환 목록을 자동으로 바꾸지는 않습니다.

별도의 합성 CI fixture에는 명시적인 native 루트 분류와 그 이름을 참조하는 process 호환 목록을 사용합니다. 이 분류는 제조사 출처를 뜻하지 않으며, 실제 provenance는 합성 입력으로 기록합니다. native 기본값에 의존하는 최소 설정이라 실제 장비용 추천 프리셋으로 배포하지 않습니다.

독립 코드 검토에서는 출력 설정의 1,200단계 배열이 재귀 비교에서 오류를 일으키고, 64단계의 비정상 래핑이 정상값으로 비교되는 문제를 재현했습니다. 디코딩한 설정의 컨테이너 깊이를 32로 제한하고 JSON 파서의 재귀 오류도 처리했습니다. 손상된 입력 프로젝트 설정은 준비 전에 차단하며, 손상된 출력 설정은 `needs_review`로 반환합니다. 선택 플레이트의 온도 0이 native에서 미지원 조합을 뜻하는 규칙도 확인해 준비 단계에서 거절하고, 미선택 플레이트의 0은 보존합니다.

그 다음 [실행 43375508617](https://github.com/uulab-official/3d-printer-agent/actions/runs/43375508617)은 두 앱 경로에서 실제 슬라이싱과 어댑터 검사를 통과했으나, 독립 검증기가 네 속도 필드의 native 출력 형식을 문자열 scalar로 예상해 실패했습니다. 고정한 `PrintConfig.cpp`의 네 필드가 `coFloats`인 것과 실제 출력의 단일 요소 배열을 확인한 후, **해당 네 기대값의 표현만** 수정했습니다. 입력 scalar는 유지하고 독립 비교의 strict equality는 완화하지 않았습니다. 최종 native CI는 이 정정과 모든 최신 어댑터 변경을 포함합니다.

마지막 독립 검토에서 401자리 JSON 정수가 숫자 비교 중 `OverflowError`를 일으키는 경우도 재현했습니다. 커밋 `2e29040`은 그 경우를 불일치로 처리해 `needs_review`를 반환하며, 실패를 먼저 확인한 회귀 검사를 추가했습니다.

## 패키지와 실제 HTTP 경로

인터넷에서 의존성을 새로 설치하지 않고 `pip install --no-index --no-deps --no-build-isolation --target ... .`로 패키지를 빌드·설치했습니다. 소스 폴더 밖에서 설치한 모듈로 서버를 시작하고 실제 HTTP 요청으로 아래 경로를 확인했습니다.

- bootstrap과 HTML·CSS·JavaScript 배포 및 응답 정책 헤더
- “14cm × 9cm × 4cm 수납함 3칸” → 실제 CAD 생성 → 파일 SHA-256 일치 → ZIP 다운로드
- 입력이 부족한 프로필의 `needs_input`, 배송비가 미확인인 상품의 단가 미확정
- 작업 이력과 사용자 보고 결과 저장

모든 HTTP 검사가 통과했습니다. 상세 기록은 [HTTP_EVIDENCE.json](HTTP_EVIDENCE.json)에 있습니다. 이는 브라우저 렌더링이나 다른 PC의 의존성 설치를 검증한 결과가 아닙니다.

## 코드 검토에서 수정한 문제

- 대상 물건 이름이 있는 필라멘트·구매 질문을 제작 요청으로 오해하는 분기를 수정했습니다.
- 새 슬라이싱이 실패했는데 이전 파일이 현재 결과처럼 남는 다운로드 별칭을 해제합니다.
- 원형 수납함·손잡이 등 알려진 미지원 형상을 기본 모델로 축약하지 않도록 확인 경로를 추가했습니다. 템플릿에 적용되지 않는 비기본 파라미터는 거절합니다.
- 개별 치수의 단위, 인셋 깊이, `.8` 표기, 서로 충돌하는 칸 수를 확인합니다.
- LLM의 자유 텍스트가 출력 완료 같은 실행 사실을 선언하지 않도록 사용자 상태 문장은 앱이 생성합니다.

규칙 파서는 제한된 문법입니다. 모든 자연어 제약의 인식을 검증했다는 뜻은 아니며, 생성 전 치수 편집과 기본값 표시를 유지합니다.

## 화면 검증의 제한

한국어 UI, 반응형 CSS, Canvas 3D 미리보기, 생성·다운로드·설정·가격·이력 연결 코드를 구현했습니다. JavaScript 문법과 HTML ID/label/DOM 참조, inline script/style/event-handler 부재를 확인했습니다.

`node tests/test_ui_state.cjs` → **4개 상태 회귀 검사 통과**. 제작안 변경 시 이전 결과 해제, 실행 없는 저장 계획 표시, 슬라이싱 준비 후 다운로드 갱신, 작업 진행 중 다른 모델 생성 잠금을 실제 컨트롤러 함수와 DOM 대역으로 검사했습니다. 이 수치는 위 Python 테스트 88개와 별도로 집계합니다.

앱의 실제 `MeshViewer` 클래스와 세 샘플의 STEP 메시를 별도의 Canvas 래스터라이저에서 실행해 이미지도 확인했습니다. 삼각형의 평균 깊이로 그리던 방식에서 내부 면이 잘못 겹치는 문제를 발견했고, 픽셀별 깊이 버퍼로 수정했습니다. [모델 미리보기 이미지](../examples/model-preview.png)는 이 검사에서 나온 실제 형상입니다. 브라우저의 CSS·이벤트·모바일 성능 검증과는 구분합니다.

초기 로컬 환경의 실제 브라우저 검사는 **완료하지 못했습니다**. Playwright 기본 브라우저가 설치되지 않았고, 사용 가능한 Chromium 실행은 환경의 IPC 소켓 정책으로 차단되었습니다. 권한 확장 요청은 설정된 자동 승인 정책에서 거절되었습니다. 정책을 바꾸거나 우회하지 않았습니다. 이후 공개 저장소의 GitHub Actions에서 실행한 브라우저 검증은 문서 상단에 별도로 기록했습니다.

초기 로컬 검사만으로는 모바일 레이아웃, 실제 픽셀 렌더링, 마우스·터치·키보드 상호작용을 확인할 수 없었습니다. 위 CI에서 확인한 경로 외에, 사용자 PC와 실제 입력 장치에서 추가로 확인할 항목은 다음과 같습니다.

1. 첫 화면의 세 템플릿과 서버 상태 표시.
2. 자연어 제작안에서 치수·기본값을 확인한 뒤 모델 생성.
3. 실제 메시 회전·확대, STL·STEP·3MF·전체 ZIP 다운로드.
4. 빈 필라멘트 JSON이 정보 입력 필요로 표시되는지 확인.
5. 배송비 미확인과 무료 배송을 구분하는 가격 비교.
6. 작업 기록 재열기와 사용자 결과 저장, 작은 화면에서 메뉴·폼 사용.
