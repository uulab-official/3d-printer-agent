# Studio 프로젝트의 필라멘트 설정 바꾸기

지원하는 Studio 프로젝트를 가져온 뒤 노즐·베드 온도, 유량 비율, 최대 체적 속도를 화면에서 바꾸고 **원본 → 입력값 차이를 확인한 다음 적용**합니다. 원본 `.3mf`는 그대로 보관합니다. 적용한 값은 현재 앱 CAD를 담은 별도 프로젝트에 들어가며, 이력과 전체 백업에도 남습니다.

이 기능은 [프로젝트 가져오기](STUDIO_PROJECTS.md)의 지원 조건을 그대로 따릅니다. Studio `02.09.01.70`, 단일 필라멘트·노즐·활성 익스트루더의 명시적인 전역 설정이 대상입니다. 별도 재료 검토 화면의 JSON이나 보고서를 자동으로 변환하는 기능은 아닙니다.

## 사용 순서

1. **프로젝트 하나로 출력 설정 준비**에서 `.3mf`를 가져오고 기록된 프린터·노즐·재료·플레이트를 확인합니다. **이 프로젝트 설정 선택**으로 적용할 원본을 고릅니다.
2. **필라멘트 설정 편집**을 누릅니다. 원본 값과 현재 입력값, 단위를 비교할 수 있습니다. CAD 생성 전에도 설정을 편집할 수 있습니다.
3. 필요한 항목을 바꾸고 **입력값과 차이 검토**를 누릅니다. 이 단계는 변경 기록을 저장하거나 프로젝트를 만들지 않습니다.
4. 표시된 **검토한 차이 · 아직 적용하지 않았습니다**를 확인하고 **검토한 차이 적용**을 누릅니다. 적용 이후 입력을 수정하면 다시 검토해야 합니다.
5. CAD를 생성하거나 현재 CAD를 확인한 뒤 **현재 CAD에 설정 담기**를 누릅니다. **설정 포함 3MF 다운로드**로 변경한 설정과 현재 CAD가 함께 들어 있는 파일을 받습니다.
6. 지원 Studio를 연결했다면 별도의 **이 프로젝트로 슬라이싱**으로 실행합니다. 준비 파일을 만들었다는 사실과 실제 Studio 슬라이싱 성공을 구분해 표시합니다.

**편집 취소 · 적용값 유지**는 입력 중인 초안을 닫고 이전 적용값을 유지합니다. **원본 설정으로 돌아가기**는 변경값 선택을 해제합니다. 기존 준비 결과는 해제되므로 현재 CAD에 다시 담아야 합니다. 원본 파일이나 저장한 변경 기록을 지우지는 않습니다.

새 프로젝트 후보를 고를 때 편집 중인 초안이 있으면 **기존 초안 유지 · 후보 취소**와 **초안 버리고 새 후보 선택** 중에서 직접 선택합니다. 미완성 숫자, 잘못 붙여 넣은 긴 문자열, 서버 오류가 발생한 입력도 자동으로 정리하거나 일부만 적용하지 않습니다.

## 편집할 수 있는 여섯 항목

| 화면 항목 | native 설정 | 지원 입력 |
|---|---|---|
| 노즐 온도 | `nozzle_temperature` | 정수 1–360 °C |
| 첫 레이어 노즐 온도 | `nozzle_temperature_initial_layer` | 정수 1–360 °C |
| 필라멘트 유량 비율 | `filament_flow_ratio` | 0 초과, 2 이하 |
| 최대 체적 속도 | `filament_max_volumetric_speed` | 0 초과, 200 mm³/s 이하 |
| 베드 온도 | 원본 플레이트의 `*_temp` | 정수 1–120 °C |
| 첫 레이어 베드 온도 | 원본 플레이트의 `*_temp_initial_layer` | 정수 1–120 °C |

이 표는 **지원하는 설정 형식의 범위**입니다. 특정 프린터가 이 온도를 지원한다거나 특정 재료에 적합하다는 뜻이 아닙니다. 변경값의 출처는 `user_selected`로 기록하며 제조사 권장값이나 실물 출력 검증으로 표시하지 않습니다. 사용 중인 장비·노즐·플레이트와 재료의 실제 조건을 확인하고 값을 입력하세요.

범위는 고정한 [Bambu Studio 소스의 `PrintConfig.cpp`](https://github.com/bambulab/BambuStudio/blob/56a57d00a591360cf41bf21383915ee5bf357be5/src/libslic3r/PrintConfig.cpp)의 자료형과 상한을 근거로 합니다. 앱은 기존 지원 조건에 따라 선택한 온도·유량·체적 속도에 양수를 요구합니다. 이 근거는 입력 검증에 사용하며 물리적인 출력 성공률을 입증하지 않습니다.

숫자는 최대 32자 문자열로 받고 앞뒤 공백은 검토 시 제거합니다. 소수는 소수점 뒤 최대 여섯 자리의 완성된 십진수만 받습니다. `0.98`은 가능하지만 `1.`, `1e2`, `NaN`, 부호가 붙은 값은 받지 않습니다. 정수 온도에는 소수점을 사용하지 않습니다. `1.000`과 원본 `1`처럼 수치가 같으면 변경으로 기록하지 않습니다.

베드 항목은 원본에 기록된 플레이트에만 연결됩니다. 이 화면에서 플레이트·프린터·재료 ID·노즐 직경·프로세스·pressure advance·G-code를 바꿀 수 없습니다. 편집할 수 없는 원본 표현이나 범위가 있으면 오류를 설명하며 원본 설정으로 준비하는 기존 경로는 유지합니다.

## 원본과 변경 기록

원본 설정을 그대로 선택하면 설정 JSON의 원문 바이트를 보존합니다. 실제 변경이 있으면 원본 전체 JSON에서 변경한 여섯 항목 중 해당 값만 교체하고, 나머지 키와 값은 유지합니다. 변경 JSON은 결정적인 형식으로 다시 직렬화하므로 원본과 파일 바이트가 같다고 표시하지 않습니다. 알 수 없는 키, 다른 플레이트의 값과 기존 코드도 이 편집으로 변경하지 않습니다.

적용마다 서버가 새로운 변경 기록 ID를 만듭니다. 기록에는 원본 ID·파일 해시·설정 해시, 검토한 차이, 적용할 설정 해시와 검토 해시가 들어갑니다. 여러 번 수정해도 항상 원본을 기준으로 한 완전한 변경값을 보관하며 이전 변경 기록을 덮어쓰지 않습니다. 바뀐 값이 없는 검토는 가능하지만 내용 없는 변경 기록을 만들지는 않습니다.

준비 파일은 원본과 현재 CAD의 별도 결과물입니다. 원본 설정 해시, 변경 후 설정 해시, 변경 기록 ID와 검토 해시를 준비 기록과 3MF 메타데이터에 함께 남깁니다. 원본을 확인했다는 것과 사용자가 값을 선택했다는 사실을 구분할 수 있습니다.

## 이력·재연결·백업

[Studio 설정 보관함](STUDIO_LIBRARY.md)에 원본·변경값과 미완성 입력을 이름 붙여 저장할 수 있습니다. CAD 작업을 만들지 않았어도 앱을 다시 열어 목록에서 찾을 수 있으며, 이전 버전에서 가져온 원본·변경 기록도 표시합니다. 저장한 초안을 다시 열었다고 검토나 적용이 완료되지는 않습니다.

작업 이력에는 당시 원본과 적용한 차이를 표시합니다. 기록을 열면 해당 변경 기록과 원본을 서버에서 다시 확인하고 후보로 보여 줍니다. 직접 선택한 뒤 새로 준비해야 합니다. 저장된 변경 기록이 없거나 손상됐으면 원본 설정만으로 바꿔 진행하지 않습니다.

서버 재연결은 화면의 초안을 보존하며 검토·적용·준비·실행 요청을 자동 재전송하지 않습니다. 다른 입력을 선택하거나 편집·취소한 이후 도착한 과거 응답은 현재 작업에 적용하지 않습니다. 새 준비에 실패하면 지난 준비·슬라이싱 파일이 현재 결과로 남지 않습니다.

[전체 백업](BACKUP_RESTORE.md)은 원본, 변경 기록, 작업 이력과 준비 파일을 함께 포함합니다. 다른 폴더로 복원해도 동일한 변경 기록 ID를 다시 읽고 새 준비를 수행할 수 있습니다. 과거 기록의 절대 경로로 실행하지 않고 복원된 폴더에서 입력을 새로 검증합니다. 변경 기록 자체는 `studio-settings-revisions/<ID>/revision.json`에 저장하며 매번 원본에서 결과를 다시 계산해 검사합니다.

## API

| 요청 | 동작 |
|---|---|
| `GET /api/studio-projects/{source_id}/settings` | 여섯 항목의 원본 값·단위·입력 범위·원본 해시 조회 |
| `POST /api/studio-projects/{source_id}/settings/review` | `{source_sha256, settings_sha256, values}` 검토 |
| `POST /api/studio-projects/{source_id}/settings/revisions` | 같은 제안에 `review_sha256`을 더해 새 기록 생성 |
| `GET /api/studio-settings-revisions/{revision_id}` | 원본·기록 재검증 후 `{revision, review, source}` 반환 |
| `POST /api/slice` | `{job_id, studio_settings_revision_id, execute}`로 준비 또는 명시적 실행 |

`values`는 표의 여섯 공개 항목 이름에 문자열을 연결한 객체이며 일부 항목만 보낼 수도 있습니다. 클라이언트가 원문 설정, 전체 변경 기록, 실행 파일 경로나 명령을 전달하지 않습니다. `studio_settings_revision_id`, `studio_project_id`, `config_bundle` 중 정확히 하나를 지정합니다. 누락 기록은 404, 저장 자료의 무결성 불일치는 409, 잘못된 제안이나 검토 불일치는 422로 구분합니다. 기존 로컬 세션·출처·요청 크기 검사가 적용됩니다.

실제 버전별 설치·브라우저·native 결과와 한계는 [검증 기록](VERIFICATION.md)에 남깁니다. 합성 설정의 자동 검사, 사용자 설정의 호환성, 실제 프린터 출력은 각각 별도의 근거가 필요합니다.

## v0.5.0에서 실제 확인한 범위

[공개 릴리스](https://github.com/uulab-official/3d-printer-agent/releases/tag/v0.5.0)의
소스는 `c88b4ee`입니다. 실제 Chromium의 데스크톱·모바일 화면 크기에서 여섯 값의
입력·검토·적용, 현재 CAD 다운로드, 실제 서버 재시작과 변경 이력 재사용을 확인했습니다.
공통 wheel의 Ubuntu·macOS·Windows 검사는 각각 183개를 통과했고, 원본과 변경 기록을
포함한 36개 파일을 복원한 뒤 같은 변경 기록으로 새 준비를 만들어 바이트까지 대조했습니다.

[실제 Linux Studio 실행](https://github.com/uulab-official/3d-printer-agent/actions/runs/43660589608)에서는
단일 재료의 합성 큐브 프로젝트 설정을 가져와 여섯 값을 바꾸고 다른 케이블 CAD를
슬라이싱했습니다. 원본 612개 설정 중 바꾸지 않은 606개 값, 변경한 여섯 값과 새 메시를
독립 대조했습니다. Studio의 허용된 세 정규화 차이도 별도로 기록했습니다. 이 수치는
합성 테스트 입력이며 재료 추천값이 아닙니다. native 로그의 진단과 실물 출력·사용자
설정에 대한 미검증 범위를 포함한 전체 결과는 [검증 기록](VERIFICATION.md)에 있습니다.
