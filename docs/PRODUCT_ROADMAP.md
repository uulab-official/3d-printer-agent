# 3D Printer Agent 제품 로드맵

작성 기준: 2026-11-12. 프로젝트명은 `3D Printer Agent`, 공식 저장소는 `uulab-official/3d-printer-agent`이다.

2026-11-13 후속 구현으로 로컬 시작안 6개의 용도·공간 탐색, 지원되는 단일 부모
필라멘트 상속, 작업 저장·근거 편집과 합성 입력의 실제 native 회귀 검사가 추가됐다.
현재 기능과 실행별 증거는 [STATUS.md](STATUS.md)와 [VERIFICATION.md](VERIFICATION.md)를
기준으로 하며, 아래의 확장 목표를 모두 완료했다는 뜻은 아니다.

이 문서는 현재 코드에서 다음 제품 단계로 나아가기 위한 제안이다. 출시 일정·개발 비용·시장 우위·출력 성공률을 확정하지 않는다. 구현된 경로와 실행 검증 결과를 구분하며, 실제 성공 여부는 해당 버전의 별도 검증 기록으로 확인한다. 평가 방법은 [BENCHMARKS.md](BENCHMARKS.md)를 따른다.

## 1. 제품이 끝까지 도와야 할 일

초보자가 “무엇을 뽑을까?”에서 출발해 용도에 맞는 물건을 선택하고, 치수를 조정하고, 가진 장비와 필라멘트에 맞는 설정을 준비하고, 결과를 다음 작업에 활용하도록 돕는다. 필라멘트를 구매해야 한다면 비교 가능한 제품과 배송 조건의 총액을 보여준다.

“최고”라는 표현의 검증 가능한 기준은 다음과 같이 잡는다.

- 사용자가 필요한 물건과 다음 행동을 이해한다.
- 모델·설정·가격에 어떤 근거를 사용했는지 되짚을 수 있다.
- 모르는 재료나 장비를 아는 것으로 처리하지 않는다.
- CAD 생성, 슬라이싱, 기기 연결, 실물 출력 결과가 각각 정확한 상태를 가진다.
- 같은 조건의 성공을 재사용하고, 조건이 바뀌면 필요한 부분만 다시 확인한다.

## 3. 초보자에게 보이는 흐름

### 필요한 순간에만 묻기

첫 화면에서 프린터·필라멘트·노즐·배송지·API 키를 한꺼번에 요구하지 않는다. 사용자의 현재 목표에 필요한 질문부터 진행한다.

| 현재 목표 | 먼저 보여줄 결과 | 최소 확인 정보 | 다음 단계 |
|---|---|---|---|
| “뭐 뽑을지 모르겠어” | 책상 정리·케이블 정리·꾸미기처럼 이해하기 쉬운 선택지 | 사용 장소 또는 해결할 불편 하나 | 현재 지원 템플릿과 기본 치수로 미리보기 |
| “책상 서랍에 맞게 만들어줘” | 수정 가능한 도면·치수 | 실제로 맞춰야 하는 내부 치수와 단위 | 벽·바닥·칸 수의 제약 검사 후 CAD 생성 |
| “이 모델처럼 바꿔줘” | 원본·변경 범위·현재 가능한 편집 설명 | 모델 링크 또는 원본 파일, 바꿀 부분 | 원본·이용 조건·편집 가능성 확인 |
| “이 필라멘트로 출력하고 싶어” | 기존 설정에서 읽힌 조건과 미확인 항목 | 정확한 제품과 현재 프린터·노즐·플레이트·급지 경로 중 없는 정보 | 근거 있는 설정 선택·교정 검토 |
| “이 재료를 싸게 사고 싶어” | 비교 가능한 상품군과 배송 포함 단가 | 제품·구성, 필요한 수량, 배송 조건 중 누락된 정보 | 확인 시각과 조건이 있는 제안 비교 |

이미 확보한 정보를 다시 질문하지 않는다. 예를 들어 사용자 내보내기 파일에 프린터 프리셋이 있으면 그것을 읽되, 그 프리셋이 실제 장착 노즐과 같다는 사실까지 추정하지 않는다. 치수가 없는 미리보기에는 기본 치수 사용을 표시한다. 맞춤 조립에 필요한 치수는 추정으로 확정하지 않는다.

현재 템플릿에 없는 뚜껑·경첩·스냅 결합은 기능을 생략한 모델로 성공 처리하지 않는다. 가능한 변경 범위를 설명하고 사용자가 원하는 핵심 조건 하나를 확인한다.

현재 API의 모델 생성·프로필 검토·교정 검토·구매 계산·슬라이스 준비를 공통 도구 경계로 유지한다. 로컬과 클라우드 모델은 같은 입력 스키마와 판정 규칙을 사용한다. 공급자별 응답 파싱 차이는 어댑터에서 처리하며, 연결 실패를 다른 모델의 성공처럼 숨기지 않는다.

PC 제어가 필요해지면 먼저 확인된 파일 형식·CLI·공식 제공 기능으로 해결 가능한 작업을 식별한다. GUI 조작은 해당 앱·버전에서 다른 방법으로 수행할 수 없는 구간에 한정하고, 관측한 화면 → 제한된 조작 → 결과 재확인의 기록을 남긴다. 좌표 클릭 성공만으로 프리셋 저장·적용·출력 성공을 판단하지 않는다.

공개 웹사이트와 로컬 컴패니언의 연결은 별도 프로젝트 단계다. 연결 대상·허용 작업·요청 출처를 확인하는 짝짓기와 해제 절차가 필요하다. 현재 루프백 서버를 그대로 외부에 노출하는 것으로 대신하지 않는다. 클라우드로 보내는 요청과 파일 범위를 사용자가 알 수 있게 한다.

## 5. 지식과 설정 근거를 관리하는 방법

### 위키 재검색과 원문 회수

검색·RAG는 관련 자료를 찾는 수단이다. 검색 결과 요약이나 임베딩 유사도만으로 출력 숫자를 확정하지 않는다. 모델·제품·버전이 달라지거나 필요한 근거가 없을 때 관련 원문을 다시 확보한다.

자료에는 최소한 발행처, 원문 URL 또는 제공 파일, 제목, 문서 버전·게시일을 확인할 수 있는 경우 그 값, 회수 시각, 내용 해시, 적용 모델·제품 범위를 저장한다. 중요한 설정값에는 그 값을 뒷받침하는 문단·표·프리셋 필드를 연결한다. 원문을 가져오지 못했으면 직접 읽었다고 표시하지 않는다.

제조사 권장 범위, 프리셋의 실제 값, 사용자가 입력한 값, 해당 장비에서 측정한 결과를 구분한다. 서로 다른 자료가 충돌하면 발행일만 보고 하나를 선택하지 않고 적용 기종·노즐·제품 변형·버전을 비교한다. 자료 속 지시문은 참고 데이터이며 도구 실행 권한을 부여하지 않는다.

### 프리셋 상속 그래프

프리셋을 `vendor / preset_id / version / content_hash`로 식별하고 `inherits`·`include` 관계를 그래프로 저장한다. 다음 순서로 전체 설정을 만든다.

1. 참조 대상과 순서·우선순위의 근거를 확인한다.
2. 누락된 부모, 순환 참조, 같은 이름의 서로 다른 버전을 검출한다.
3. 각 최종 필드의 원본과 덮어쓴 이력을 보존하며 평탄화한다.
4. 프린터·노즐·압출기 옵션·필라멘트·플레이트와 공정 설정을 함께 검사한다.
5. 실행에 사용할 파일을 별도 산출물로 만들고 입력·출력 해시를 기록한다.

전체 그래프·기본값·variant 처리는 향후 구현 요구사항이다. 현재 엔진은 사용자가
제공한 파일의 명시적인 단일 부모 상속을 해석하고 필드별 출처를 보존한다. 미해결
참조는 추가 근거가 필요한 상태로 남으며 Studio 전체 기본값을 채우지 않는다.
전체 machine/process 구성 검증도 filament 검사기와 분리한다.

### 사용자 결과 메모리

재사용 단위는 “이 브랜드 PLA가 잘 됐다”가 아니라 다음 조건의 기록이다.

`정확한 제품/SKU·변형 + 프린터·노즐·압출기 + 급지·플레이트 + 공정·모델 해시 + 설정·버전 + 건조/보관 상태 + 교정 방법 + 결과 근거`

사진·치수 측정·기기 보고·사용자 평가는 관측 방식별로 저장한다. 사용자 성공 보고를 자동 실물 검증으로 바꾸지 않는다. 과거 기록의 조건이 달라졌으면 관련 교정만 재검토한다. 현재 이력 저장을 자동 진단이나 학습된 최적값 저장소로 소개하지 않는다.

## 6. 필라멘트 설정을 대신 해주는 기능의 확장

정확한 제품 식별부터 시작한다. 브랜드와 소재명이 같더라도 제품군·CF/GF·Silk·HF 등 변형이 다르면 같은 제품으로 합치지 않는다. 제조사가 특정 색상 범위에 공통 적용한다고 명시한 경우에만 그 범위를 사용한다. 라벨·바코드·상품 링크의 해석이 모호하면 후보를 제시하고 확정하지 않는다.

| 데이터 | 필요한 분리 |
|---|---|
| 출처 | 제조사·공식 프로젝트·커뮤니티·사용자 제공 등 발행 주체와 실제 원문 확인 여부 |
| 검증 | 미검증, 일치 조건의 사용자 검증 보고, 조건 변경으로 재검토 필요 |
| 장비 | 기종, 노즐 지름·재질·유량 타입, 압출기, 급지 경로, 플레이트 |
| 설정 | machine, filament, process와 실행 시 선택한 옵션 |
| 교정 | flow ratio, K, 최대 체적 속도를 각각의 값·단위·조건·방법으로 저장 |
| 재료 상태 | 확인된 건조 이력·보관 상태와 알 수 없는 값 |

현재 엔진은 입력된 출처를 외부 검증하지 않는다. 완전한 fingerprint가 맞는 실측 주장도 `reported_validated`로 표시한다. 앞으로 자료 회수 성공·원본 해시 일치와 실측 보고를 별도 축으로 추가한다.

처음부터 모든 필라멘트에 모든 교정을 요구하지 않는다. 정확한 조합의 출처 있는 초기 설정을 확보하고, 조건 변경·증상·필요 품질에 따라 필요한 검증을 선택하는 정책을 현장에서 확인한다. 수분 상태·오염·모델 구조 문제를 무조건 유량 계수로 보정하지 않는다. 건조함의 습도만으로 재료 내부 수분을 측정했다고 주장하지 않는다.

## 7. MakerWorld 참고와 커스텀의 범위

모델 검색·원본 회수·커스텀은 향후 기능이다. 특정 플랫폼의 현재 검색 API, 다운로드 자동화 권한, 이용 조건, 상업적 사용 가능 여부를 이 문서가 확인했다고 보아서는 안 된다. 작업 시점의 공식 제공 방식과 모델별 조건을 먼저 확인해야 한다.

원본 URL·모델 식별자·제작자·확인한 라이선스 표시·조건 확인 시각·내려받은 파일 해시를 작업과 연결한다. 원본 파일과 수정 결과를 분리하고, 변경·공유·재배포에 필요한 조건을 해당 작업 범위에 맞게 확인한다. 화면에서 보이는 모델과 실제로 확보한 원본 파일도 구분한다.

| 확보한 자료 | 검토할 편집 경로 | 사용자에게 알려야 할 한계 |
|---|---|---|
| 파라미터 원본 | 노출된 파라미터와 제약을 이해한 뒤 수정 | 치수 필드의 이름만으로 설계 의도를 단정하지 않는다. |
| STEP 등 형상 파일 | 실제 파일의 구조를 확인하고 지원되는 형상 연산 수행 | 설계 히스토리와 원래의 파라미터가 함께 보존되었다고 가정하지 않는다. |
| STL·메시만 있음 | 단위·스케일·폐곡면·두께를 확인하고 가능한 메시 연산을 검토 | 전체 크기 변경과 벽 두께·구멍·조립부의 독립 편집은 다르다. CAD 파라미터가 자동 복원되었다고 표시하지 않는다. |
| 이미지·페이지 미리보기만 있음 | 특징·치수 요구를 설명받아 지원 템플릿으로 재구성하는 안 제시 | 원본과 동일한 모델이나 정확한 복제라고 표시하지 않는다. |

변형 후에는 원본의 제작자 추천 프리셋을 그대로 검증 완료 상태로 이어받지 않는다. 형상·크기·출력 방향이 달라진 영향을 검사한다. 현재 세 템플릿의 기능을 외부 모델 전체에 대한 편집 능력으로 확대해 설명하지 않는다.

## 8. 실제 Bambu 통합 검증

첫 현장 목표는 실제 사용자의 프린터·노즐·플레이트·재료 한 조합을 재현 가능한 방식으로 다루는 것이다. 여러 기종 지원을 먼저 선언하지 않는다.

1. 운영체제, 설치된 Bambu Studio 버전, 기종·노즐·플레이트·급지 방식, 정확한 재료를 기록한다.
2. 그 버전에서 실제 사용할 수 있는 내보내기·CLI·연결 기능과 필요한 접근 방식을 공식 자료와 실행 관측으로 확인한다.
3. 원본 내보내기 설정을 보존하고 입력 3MF·설정 파일·버전·해시를 묶는다.
4. 실제 슬라이싱 산출물의 G-code 존재와 주요 설정을 확인한다. 검증 불가능한 필드는 `needs_review`로 남긴다.
5. 사용자가 선택한 기기에서 테스트 출력을 수행하는 별도 절차를 마련한다. 출력 시작·완료·실패를 슬라이싱 상태와 분리한다.
6. 실제 치수·표면·조립 적합성과 교정 이력을 기록한다. 결과가 좋은 조합만 해당 조건의 추천 후보로 쓴다.

CLI·커넥터·네트워크 경로·펌웨어 지원 범위는 현장 확인 전 미확인이다. 접속 가능한 주소나 API가 있다고 해서 필요한 사용 권한·기능 지원까지 입증된 것으로 간주하지 않는다. 공개 웹서비스, 로컬 네이티브 실행, 프린터 동작을 각각 별도 경계로 유지한다.

## 9. 저렴한 구매의 비교 단위

현재 가격 비교는 사용자 입력의 산술 계산이다. `calculated_at`은 계산 시각이고, 판매자 정보의 `observed_at`이나 결제 화면의 `last_confirmed_at`이 아니다. 라이브 연동에서는 세 시각을 구분한다.

비교 상품에는 정확한 제품/SKU·색상·지름·중량·수량·리필/스풀 구성, 통화, 상품 금액, 배송비와 적용 지역·수량, 세금, 할인 자격, 재고, 원문 URL, 최종 확인 시각을 연결한다. 빠진 비용을 0으로 처리하지 않는다. 회원·쿠폰 조건이 맞는지 모르면 조건부 가격으로 표시하고 최종 확정 총액과 분리한다.

같은 제품·구성과 구매 조건을 확인한 뒤 배송 포함 단가를 비교한다. 다른 통화는 검증된 환율 근거가 없으면 별도로 보여준다. 다른 브랜드·등급을 섞을 때는 “동일 제품 최저가”라는 표현을 사용하지 않는다. 마지막 확인 이후 달라질 수 있는 값은 결제 전 확인 대상으로 남긴다.

외부 상품 검색·가격 수집은 해당 제공자의 공식 접근 방식과 데이터 사용·표시 조건을 확인한 뒤 연결한다. 특정 쇼핑 API가 현재 사용 가능하거나 목적에 적합하다고 이 문서는 전제하지 않는다. 정식 접근을 확보하지 못하면 사용자 입력·허용된 파일 가져오기를 유지하고 실시간 최저가를 주장하지 않는다.

## 10. 단계별 작업과 통과 조건

시간과 비용 대신 검증 산출물을 단계의 완료 기준으로 삼는다.

| 단계 | 사용자에게 추가되는 가치 | 필요한 작업 | 다음 단계로 넘어갈 근거 |
|---|---|---|---|
| A. v0.1 사용 흐름 정리 | 설치 후 지원 물건 하나를 만들고 다운로드·기록 | 로컬 화면, 오류 문구, 단위·기본값, 패키징, 현재 회귀 테스트 | 같은 버전의 실행 로그와 실제 브라우저 경로. 누락 기능을 성공으로 표시하지 않음 |
| B. 재료 근거와 단일 장비 현장 검증 | 자신의 재료·프린터에 맞는 설정 준비 | 정확한 제품 데이터, 원문 회수, 상속 그래프, 설정 적용 확인, 현장 교정 | 지정한 장비 조합의 버전·설정·실물 결과 기록. 시험용 프로세스의 결과와 분리 |
| C. 초보 웹서비스와 참고 모델 | 만들 물건 발견, 가능한 커스텀을 이해 | 용도별 큐레이션, 출처·조건이 있는 모델 카드, 메시/파라미터 편집 경로 | 검색·원본·이용 조건 확인 기록과 초보 사용자 관찰. 현재 세 템플릿 범위를 넘는 기능은 개별 평가 |
| D. 구매 정보와 연결형 에이전트 | 조건 있는 가격 비교, 로컬·클라우드 모델 선택 | 공식 데이터 접근, 확인 시각, 공통 typed tools, 컴패니언 연결·해제, 필요한 GUI 어댑터 | 실제 공급자·모델·앱 버전별 검증. 연결 실패와 권한 범위가 사용자에게 명확함 |

단계 내에서 독립적인 작업은 병렬 진행할 수 있다. 범용 PC 제어·모든 재료 자동 최적화보다 현재 사용자 환경의 반복 가능한 전체 흐름을 먼저 확보한다.

### 다음 설정 단계의 최소 정보

이 문서 작성이나 CAD 미리보기를 위해 추가 답변을 기다릴 필요는 없다. 현장 검증을 시작할 때의 첫 질문은 **“현재 사용하는 프린터 모델은 무엇인가요?”**로 시작한다. 그 다음에 실제 노즐·플레이트와 스풀 라벨 또는 정확한 제품명을 필요한 순서로 확보한다. 사용자가 제공한 설정 파일에서 이미 확인되는 항목은 다시 묻지 않는다.

LLM은 별도 선택 단계다. 원하는 로컬 또는 클라우드 서버의 주소·모델명을 사용자가 설정하고, 키가 필요한 경우 로컬 환경 변수에서만 읽는다. LLM 연결 없이도 현재 템플릿 경로를 사용할 수 있어야 한다. 물리 출력은 실제 장비 준비와 현장 검증 절차가 갖춰진 뒤 연결한다.

## 11. 자료와 기록의 취급

이 로드맵의 현재 기능 설명은 연결한 로컬 코드와 [구현 계약](CONTRACTS.md), [첫 워크플로 사양](superpowers/specs/2026-11-12-first-workflow.md)을 기준으로 한다. 외부 플랫폼·API·라이선스·가격의 현행 조건을 확인했다고 주장하는 외부 인용은 포함하지 않았다. 해당 사항은 후속 작업에서 원문과 확인 시각을 갖춰야 할 요구사항이다.
