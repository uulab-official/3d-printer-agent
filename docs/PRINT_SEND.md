# 프린터로 보내기 (LAN)

v0.15부터 앱에서 슬라이싱을 마친 모델을 같은 네트워크의 Bambu 프린터에 올리고 출력을 시작할 수 있습니다.
**실제 프린터가 움직이는 기능**이므로, 시작할 때마다 확인을 거칩니다.

## 준비

- 프린터 화면의 네트워크 설정에서 **LAN 전용 모드**를 켜고, 그 아래의 **개발자 모드**를 켭니다.
  최근 펌웨어는 이 모드에서만 다른 프로그램의 MQTT·FTP 접속을 받습니다. 이 모드에서는 Bambu Handy·클라우드
  기능을 쓸 수 없으며, Bambu는 이 모드에서의 외부 프로그램 동작을 보증하지 않는다고 안내합니다.
- 앱의 **프린터 상태** 화면에 IP 주소·시리얼·LAN 액세스 코드를 입력합니다. 액세스 코드는 저장하지 않습니다.
- 현재 모델을 앱에서 **슬라이싱 완료**해야 합니다(한 판의 G-code가 든 슬라이스 3MF).

## 순서

1. 모델 화면의 **프린터로 보내기**에서 **보내기 전 확인**을 누릅니다. 프린터 상태를 한 번 읽어 다음을 확인합니다.
   - 프린터가 대기·완료·실패 상태인지(출력 중·일시 정지면 보내지 않음)
   - 프린터가 보고한 노즐 지름과 슬라이스한 노즐 지름이 같은지
   - 슬라이스한 필라멘트마다 꽂힌 위치(AMS 칸 또는 한 색일 때 외부 스풀)를 골랐는지, 재료 종류가 다르면 경고
2. 확인을 통과하면 3분 동안 쓸 수 있는 1회용 확인이 만들어집니다. 칸 선택이나 프린터 입력을 바꾸면 다시 확인해야 합니다.
3. **출력판이 비어 있고 필라멘트가 꽂혀 있음을 직접 확인**했다는 칸에 표시하고 **출력 시작**을 누릅니다.
4. 앱은 프린터 상태를 다시 확인하고, 파일을 FTPS(990)로 올려 크기를 확인한 뒤, MQTT로 시작 명령을 보내고
   최대 30초 동안 프린터의 시작 보고를 기다립니다.

## 결과

| 상태 | 의미 |
|---|---|
| `started` | 프린터가 이 작업 이름으로 출력 준비·출력 중을 보고함 |
| `unconfirmed` | 명령은 보냈지만 제한 시간 안에 시작 보고를 받지 못함 → 프린터 화면 확인 |
| `rejected` | 프린터가 오류 코드를 보고함 |
| `blocked` | 프린터가 대기 상태가 아니어서 보내지 않음 |
| `failed` | 업로드나 연결이 실패함 |

“대기 상태 확인 → 파일 올리기 → 시작 명령 → 프린터의 시작 보고”를 따로 표시하고 작업 기록에 남깁니다.
프린터의 시작 보고는 실물 품질·치수의 측정이 아닙니다. 출력 결과는 기존처럼 직접 기록하세요.

## 검증 범위

- 자동 검사: 합성 프린터(`scripts/fake_bambu_printer.py --ftps-port`)의 MQTT·암묵적 FTPS를 상대로 검토·업로드·명령·
  시작 보고·거부·바쁜 프린터·노즐 불일치·파일 변경·토큰 재사용을 확인합니다.
- 이 Mac에서 실제 Bambu Studio 02.09.01.70으로 슬라이싱한 키링을 브라우저에서 합성 프린터로 보내 `started`까지 확인했습니다.
- **실제 프린터로는 아직 검증하지 않았습니다.** 시작 명령의 파일 경로(`file:///sdcard/…`)와 필드는 커뮤니티에 공개된
  사용 예를 따른 것이며 모델·펌웨어에 따라 다를 수 있습니다. 처음 보낼 때는 프린터 옆에서 지켜보세요.
- 두 색 키링은 아직 앱 안에서 두 필라멘트로 슬라이싱하지 못합니다. 앱에서 보낼 수 있는 것은 앱이 슬라이싱한 파일입니다.

로컬에서 합성 프린터로 시험하기:

```bash
python scripts/fake_bambu_printer.py --access-code abcd1234 --state IDLE --ftps-port 2990
PPA_PRINTER_FTPS_PORT=2990 python -m print_agent
```
