# 프린터로 보내기 (LAN)

v0.15부터 앱에서 슬라이싱을 마친 모델을 같은 네트워크의 Bambu 프린터에 올리고 출력을 시작할 수 있습니다.
**실제 프린터가 움직이는 기능**이므로, 시작할 때마다 확인을 거칩니다.

## 준비

- 프린터 화면의 네트워크 설정에서 **LAN 전용 모드**를 켜고, 그 아래의 **개발자 모드**를 켭니다.
  최근 펌웨어는 이 모드에서만 다른 프로그램의 MQTT·FTP 접속을 받습니다. 이 모드에서는 Bambu Handy·클라우드
  기능을 쓸 수 없으며, Bambu는 이 모드에서의 외부 프로그램 동작을 보증하지 않는다고 안내합니다.
- 앱의 **프린터 상태** 화면에 IP 주소·시리얼·LAN 액세스 코드를 입력합니다. 액세스 코드는 저장하지 않습니다.
- 현재 모델을 앱에서 **슬라이싱 완료**해야 합니다(한 판의 G-code가 든 슬라이스 3MF).

## 순서

1. 모델 화면의 **프린터로 보내기**에서 **보내기 전 확인**을 누릅니다. 프린터 상태를 한 번 읽어 다음을 확인합니다.
   - 프린터가 대기·완료·실패 상태인지(출력 중·일시 정지면 보내지 않음)
   - 프린터가 보고한 노즐 지름과 슬라이스한 노즐 지름이 같은지
   - 슬라이스한 프린터 기종(파일의 `printer_model_id`)과 프린터가 보고한 제품 이름이 같은 기종인지. 보고된 이름이 이 앱이 아는
     **다른** 기종(X1 Carbon·X1·X1E·P1P·P1S·A1 mini·A1·H2D)과 정확히 같으면 보내지 않습니다. 출력판 크기와 시작 동작이 달라 헤드가 부딪칠 수 있기 때문입니다.
     이름이 없거나 형식을 알 수 없으면 비교하지 못했다고 경고만 합니다. 실제 기기가 보고하는 제품 이름 형식은 아직 실기로 확인하지 않았습니다.
   - 슬라이스한 재료 중 섬유가 든 마모성 필라멘트(종류 이름이 `-CF`·`-GF`로 끝남)가 있는데 프린터가 스테인리스강·황동 노즐을 보고하면
     경화강 노즐을 권하는 경고(보내기는 막지 않음). 노즐 재질을 보고하지 않으면 확인하라고 경고합니다.
   - 슬라이스 파일의 필라멘트별 노즐 온도(`Metadata/project_settings.config`)가 고른 AMS 칸이 보고한 권장 범위를 벗어나면 경고(보내기는 막지 않음).
     온도나 범위가 보고되지 않으면 비교하지 않습니다. AMS 칸 정보는 프린터·RFID가 보고한 값이며 실물 확인이 아닙니다.
   - 슬라이스한 필라멘트마다 꽂힌 위치(AMS 칸 또는 한 색일 때 외부 스풀)를 골랐는지, 재료 종류가 다르면 경고
2. 확인을 통과하면 3분 동안 쓸 수 있는 1회용 확인이 만들어집니다. 칸 선택이나 프린터 입력을 바꾸면 다시 확인해야 합니다.
3. **출력판이 비어 있고 필라멘트가 꽂혀 있음을 직접 확인**했다는 칸에 표시하고 **출력 시작**을 누릅니다.
4. 앱은 프린터 상태를 다시 확인하고, 파일을 FTPS(990)로 올려 크기를 확인한 뒤, MQTT로 시작 명령을 보내고
   최대 30초 동안 프린터의 시작 보고를 기다립니다.

## 프린터 기억하기

프린터 상태 화면에서 **이 브라우저에 프린터 기억하기**를 켜고 상태를 읽으면 IP·시리얼·제품 이름·인증서 지문을 이 브라우저에만
저장합니다. **액세스 코드는 저장하지 않습니다.** 다음에 열면 마지막 프린터가 채워지고, 저장한 인증서 지문과 다른 장치가 응답하면
액세스 코드를 보내기 전에 멈춥니다. 기억한 프린터는 목록에서 고르거나 삭제할 수 있습니다.

## 출력 진행 따라보기

출력 시작 보고를 받으면 카드 아래에 진행 막대가 생기고 5분마다(버전 조회 없이) 프린터 상태를 다시 읽어 상태·진행률·남은 시간·레이어를 보여 줍니다.
P1·A1 계열은 전체 상태 요청이 잦으면 느려질 수 있다는 안내가 있어 간격을 길게 두었고, **지금 다시 읽기**로 바로 갱신할 수 있습니다.
프린터가 완료·실패·대기 상태를 보고하거나, 프린터 입력이 바뀌거나, 12시간이 지나거나, **자동 갱신 멈추기**를 누르면 멈춥니다.
완료 보고는 프린터의 보고일 뿐이니 출력물을 확인하고 결과를 기록하세요.

따라보는 동안 프린터가 **이 작업 이름**(`printer-agent` + 작업 번호 앞 8자리)으로 완료나 실패를 보고하면, 그 보고를 작업 기록에
“프린터 보고”로 남깁니다. 이 모델을 같은 프린터로 보내 시작 보고를 받은 작업에만 연결하고, 같은 보고는 한 번만 남깁니다.
상태·진행률·레이어와 프린터가 보낸 오류 코드(`print_error`)와 HMS 코드를 Bambu Lab 검색 형식(예: `0300-400C`,
`0700-8000-0002-0001`)으로 그대로 보관합니다. 사용자가 고르는 출력 결과와는 따로 보관하며 결과를 자동으로 고르지 않습니다.

실패 보고가 있으면 결과 카드의 “다음에 바꿔 볼 것” 맨 위에 **프린터가 보고한 실패**가 나오고, 코드가 있으면
[Bambu Lab HMS 검색](https://wiki.bambulab.com/en/hms/home) 링크를 함께 보여 줍니다. 앱은 코드의 뜻을 추측하지 않습니다.

## 일시정지·재개·정지

진행 막대 아래에 프린터가 보고한 상태에 맞는 버튼만 보입니다. 출력 중이면 **일시정지**·**정지…**, 일시정지 중이면 **재개**·**정지…**,
출력 준비 중이면 **정지…**입니다. 정지는 “되돌릴 수 없습니다” 확인을 한 번 더 거치며, 일시정지·재개가 응답을 기다리는 중에도 바로 보낼 수 있습니다. 명령은 앞서 확인해 고정한 인증서와
현재 액세스 코드가 있을 때만 보내고, 보낸 뒤 프린터가 바뀐 상태를 보고하는지 최대 15초 기다립니다. 사용자가 정지한 작업도
프린터는 “실패”로 보고할 수 있습니다. 보낸 명령은 작업 기록에 남습니다(액세스 코드 제외). 이동·온도·G-code 같은 다른 명령은 없습니다.

## 결과

| 상태 | 의미 |
|---|---|
| `started` | 프린터가 이 작업 이름으로 출력 준비·출력 중을 보고함 |
| `unconfirmed` | 명령은 보냈지만 제한 시간 안에 시작 보고를 받지 못함 → 프린터 화면 확인 |
| `rejected` | 프린터가 오류 코드를 보고함 |
| `blocked` | 프린터가 대기 상태가 아니어서 보내지 않음 |
| `failed` | 업로드나 연결이 실패함 |

“대기 상태 확인 → 파일 올리기 → 시작 명령 → 프린터의 시작 보고”를 따로 표시하고 작업 기록에 남깁니다.
프린터의 시작 보고는 실물 품질·치수의 측정이 아닙니다. 출력 결과는 기존처럼 직접 기록하세요.

## 검증 범위

- 자동 검사: 합성 프린터(`scripts/fake_bambu_printer.py --ftps-port`)의 MQTT·암묵적 FTPS를 상대로 검토·업로드·명령·
  시작 보고·거부·바쁜 프린터·노즐 불일치·파일 변경·토큰 재사용을 확인합니다.
- 이 Mac에서 실제 Bambu Studio 02.09.01.70으로 슬라이싱한 키링을 브라우저에서 합성 프린터로 보내 `started`까지 확인했습니다.
- **실제 프린터로는 아직 검증하지 않았습니다.** 시작 명령의 파일 경로(`file:///sdcard/…`)와 필드는 커뮤니티에 공개된
  사용 예를 따른 것이며 모델·펌웨어에 따라 다를 수 있습니다. 처음 보낼 때는 프린터 옆에서 지켜보세요.
- 두 색 키링은 아직 앱 안에서 두 필라멘트로 슬라이싱하지 못합니다. 앱에서 보낼 수 있는 것은 앱이 슬라이싱한 파일입니다.

로컬에서 합성 프린터로 시험하기:

```bash
python scripts/fake_bambu_printer.py --access-code abcd1234 --state IDLE --ftps-port 2990
PPA_PRINTER_FTPS_PORT=2990 python -m print_agent
```
