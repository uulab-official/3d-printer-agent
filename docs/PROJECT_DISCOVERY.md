# 만들거리 찾기

**용도와 놓을 공간을 고르고, 측정 안내를 확인한 뒤 실제 CAD 생성으로 이어지는 로컬 기능**입니다.
이 저장소의 세 가지 파라메트릭 모델에 서로 다른 초기 치수를 적용한 시작안 6개를 제공합니다.
모델 서버, 외부 검색 서비스나 API 키가 필요하지 않습니다.

## 사용할 수 있는 시작안

아래 치수는 편집 가능한 설계의 초기값이며, 사용자의 물건을 측정한 값이나 출력 설정이 아닙니다.

| 용도 | 시작안 | 초기 외곽 크기 · mm | 먼저 측정할 것 |
|---|---|---|---|
| 책상·서랍 정리 | 작은 물건 트레이 | 90 × 60 × 18 | 놓을 공간과 담을 물건 |
| 책상·서랍 정리 | 세 칸 책상 정리함 | 150 × 90 × 30 | 놓을 공간과 각 칸에 담을 물건 |
| 책상·서랍 정리 | 두 칸 서랍 트레이 | 180 × 100 × 35 | 서랍 안쪽 치수와 닫힐 때의 여유 높이 |
| 케이블 정리 | 세 줄 케이블 받침 | 50 × 18 × 12 | 케이블의 실제 바깥 지름 |
| 케이블 정리 | 다섯 줄 케이블 받침 | 80 × 18 × 12 | 케이블의 실제 바깥 지름과 배치 공간 |
| 사진·장식 | 원형 사진 인셋 프레임 | 65 × 65 × 7 | 넣을 원판의 지름과 두께 |

트레이의 벽·칸막이는 내부 공간을 차지합니다. 케이블 받침은 위가 열린 홈이고
스냅 고정장치가 아닙니다. 프레임은 원형 포켓이며 걸이·스탠드·자석 고정 구조를
추가하지 않습니다. 초기 케이블 지름 6 mm와 원판 지름 52 mm도 실제 물건에 맞게
확인하고 편집해야 합니다.

## 화면에서 사용하는 순서

1. **모델 만들기 → 만들거리 찾기**에서 용도를 선택합니다.
2. 필요하면 놓을 공간의 가로·세로·높이 중 아는 값만 mm로 입력하고 **조건으로 찾기**를 누릅니다.
3. 카드를 눌러 용도, 먼저 측정할 곳, 포함된 구조와 출처를 확인합니다.
4. **이 시작점으로 치수 준비**를 누릅니다. 기존 입력이나 모델이 있다면 교체 여부를 선택합니다.
5. 기존 치수 편집기에서 값을 조정하고 **CAD 모델 생성하기**를 누릅니다.
6. 생성한 파일과 생성 기록을 다운로드하거나 작업 기록에서 다시 엽니다.

카드를 둘러보거나 조건을 변경하는 동안 입력 중인 치수·요청과 생성된 결과는
유지됩니다. 교체를 취소하면 미완성 숫자 입력도 그대로 남습니다. 이전 조건의
검색 결과는 새 조건으로 다시 찾기 전까지 현재 조건의 추천으로 적용하지 않습니다.
연결 실패가 나면 기존 제작안을 유지한 상태에서 다시 찾을 수 있습니다.

## 공간 비교가 뜻하는 것

입력한 축만 시작안의 **외곽 크기**와 비교합니다. 원래 가로·세로로 들어가지
않으면 수평으로 90도 돌린 배치도 비교합니다. 높이를 다른 축으로 바꾸거나 크기를
자동 축소하지 않습니다. 회전 결과를 선택해도 제작안 자체의 치수는 원래 설계대로입니다.

예를 들어 가로 60·세로 90·높이 18 mm의 공간에는 작은 물건 트레이가 회전 배치로
표시됩니다. 이것은 시작안의 90 × 60 × 18 mm 외곽을 수치 비교한 결과입니다.
여유 간격, 서랍 턱, 내용물의 내부 맞춤이나 실제 출력 오차를 고려한 판정이 아닙니다.
치수를 수정하면 이 비교 결과를 그대로 적용하지 말고 다시 확인하세요.

입력값은 유한한 양수이고 10000 mm 이하이어야 합니다. 모르는 축은 비워 둡니다.
조건에 맞는 초기 크기가 없으면 빈 결과를 표시하고 조건 변경·기본 템플릿 편집으로
이어집니다. 프린터 모델이나 베드 호환성, 서포트·브림·출력 방향, 재료·시간·비용은
이 기능에서 판정하지 않습니다.

## 시작 설계와 실제 생성값

선택한 시작안의 출처는 서버의 카탈로그에서 확인합니다. 클라이언트가 임의로
제작자·라이선스·검증 상태를 넣는 경로는 없습니다. 작업과 `manifest.json`, 전체
ZIP 묶음에는 다음 항목이 함께 남습니다.

- `design_source.recipe`: 선택한 당시의 제목, 설명, 초기 파라미터, 저장소 원본 출처.
- `design_source.recipe_sha256`: 위 시작안을 식별하는 내용 해시.
- `design_source.customized`, `changed_parameters`: 초기값에서 달라진 실제 파라미터.
- `parameters`: 생성에 사용한 실제 치수. 기존 파일 해시와 재현용 Python 소스도 유지합니다.

작업 기록은 저장된 출처를 읽습니다. 현재 카탈로그에서 비슷한 치수를 찾아 출처를
새로 붙이지 않습니다. 기본 템플릿·새 요청 해석으로 전환하거나 **출처 연결 해제**를
선택하면 새 생성에는 카탈로그 출처를 붙이지 않습니다. 연결 해제는 현재 치수 입력을
보존하며 이전 생성 파일은 작업 기록에 남습니다.

이전 작업의 시작안이 이후 변경됐다면 재생성 요청은 충돌을 알려 줍니다. 현재
시작안을 다시 선택하거나 출처를 명시적으로 해제하여 편집 중인 치수로 이어갈 수
있습니다. 이 기록은 설계의 출발점을 추적하는 기능이며 실물 출력 인증이 아닙니다.

## 로컬 API

기존 루프백 서버와 세션 경계를 사용합니다. 쓰기 방식의 요청에는 현재 앱의
`X-Session-Token`과 `Content-Type: application/json`이 필요합니다.

### 카탈로그와 추천

`GET /api/bootstrap`의 `discovery`에 `schema_version`, `purposes`, `projects`가 추가됩니다.
기존 `templates`는 그대로 세 개입니다.

`POST /api/discovery`:

```json
{
  "purpose": "organization",
  "available_space": {"width": 60, "depth": 90, "height": 18}
}
```

`purpose`는 `all`, `organization`, `cables`, `display` 중 하나입니다. 생략하면
`all`, 공간은 빈 객체로 처리합니다. 누락되거나 `null`인 축은 미확인입니다.
문자열 숫자·불리언·알 수 없는 필드·음수·0은 거절합니다.

응답은 정규화된 `query`, 해당 용도의 수 `total_in_purpose`, 크기로 제외한 수
`excluded_count`, `matches`, 비교 범위 `limits`를 담습니다. 각 match에는 원본
카드 `project`, 설명 `reason`, `space_fit`이 있습니다. 크기를 확인하지 않으면
`not_checked`, 원래 배치는 `fits`, 수평 회전은 `fits_rotated`입니다.
`orientation`, `checked_axes`, 비교한 `dimensions_mm`도 기록합니다. 반환 순서는
카탈로그 순서이며 개인화 점수나 인기 순위를 만들지 않습니다.

### 생성 요청의 선택적 출처

`POST /api/models`는 기존의 평면 geometry JSON을 그대로 받습니다. 시작안을
선택한 경우에만 다음 필드를 추가합니다.

```json
{
  "project_selection": {
    "id": "desk-sorter",
    "recipe_sha256": "카탈로그가 반환한 실제 64자리 소문자 SHA-256"
  }
}
```

위는 추가 필드의 구조 설명이며 그대로 실행하는 요청이 아닙니다. 같은 본문에
기존 `template`과 실제 치수를 포함해야 합니다. `project_selection`은 geometry
파라미터에 포함되지 않고 별도로 처리됩니다.

서버는 ID·현재 해시·템플릿 일치를 작업 예약 전에 검사합니다. 모르는 ID나 다른
템플릿·임의 출처 필드는 HTTP 422, 변경된 시작안 해시는 HTTP 409입니다.
유효한 출처가 있더라도 기존 CAD 형상 검사를 생략하지 않습니다. 선택을 생략한
요청과 과거 작업에는 출처를 추정해서 추가하지 않습니다.

### 해시 계산

시작안 해시는 `recipe_sha256`을 제외한 전체 카드에 대해 계산합니다. 서버가
정규화한 float/int 표현을 포함한 Python JSON 형식을 사용하며, 다른 언어에서
숫자 표현을 바꾸어 재직렬화한 문자열의 해시와 같다고 가정하지 않습니다.

```python
canonical = json.dumps(recipe, ensure_ascii=False, sort_keys=True,
                       separators=(',', ':'), allow_nan=False).encode('utf-8')
digest = hashlib.sha256(canonical).hexdigest()
```

클라이언트는 카탈로그의 해시를 그대로 선택 참조로 전달합니다. 설계 시작안의
해시와 생성 파일·재현용 소스의 해시는 서로 다른 대상을 식별합니다.
